## Overall Assessment

The current UI direction is credible for an iOS creative tool. The strongest parts are:

- Bottom tab navigation already matches the app's two-to-three core destinations better than the previous top capsule navigation.
- Capture flow now communicates `现场取景 -> 参考图详情 -> 保存到灵感库`.
- Structured prompt and `我当时想到` make the product feel different from a generic camera or AR placement tool.
- The visual language has a coherent warm/sage direction that fits a private visual diary.

The main issue is not missing features, but HIG polish. Some controls are visually small, glass is applied too broadly, custom gestures need visible alternatives, and the library/detail pages need more native iOS information hierarchy.

## HIG Findings

### 1. Bottom Tab Bar Needs More Native iOS Proportions

Current state:

- `RootTabView` uses a custom bottom tab bar with three items.
- Labels use `.caption2`, which is quite small.
- The bar visually works, but it is not yet close enough to native iOS tab bar rhythm.

Problems:

- `.caption2` can feel too small for a primary navigation label.
- Custom tab bar height should clearly reserve safe-area space and provide at least 44pt touch area per tab.
- Selected state currently relies mostly on color; filled SF Symbols are good, but selected state can be more obvious.

Recommended changes:

- Use `.footnote.weight(.semibold)` or `.caption.weight(.semibold)` for tab labels instead of `.caption2`.
- Keep each tab's tappable area at least 44pt high.
- Use selected symbol fill + accent color + subtle selected background or top indicator.
- Keep text labels visible for every tab.
- Consider `safeAreaInset(edge: .bottom)` for the actual tab bar rather than overlaying a custom bar with manual content spacing.

Files:

- `SceneZero/SceneZero/Views/RootTabView.swift`

Priority: high.

### 2. Capture Top Bar Buttons Are Visually Smaller Than Their Touch Intent

Current state:

- Reset and composition guide buttons render at 30-32pt in `topBar`.
- They sit inside a larger glass capsule.

Problems:

- HIG minimum touch target is 44x44pt.
- Even if the surrounding capsule is tappable visually, each button's visible affordance reads small.
- Icon-only controls need clear labels for VoiceOver; accessibility labels exist, which is good.

Recommended changes:

- Keep visible circle around 32-36pt if desired, but wrap each button in a 44x44pt frame.
- Use `.contentShape(Rectangle())` on each button.
- Keep `accessibilityLabel`, and consider adding `accessibilityHint` for less obvious controls:
  - `重置场景`
  - `显示或隐藏构图辅助线`
- Use SF Symbols outline style for inactive toolbar icons and filled style only for selected/toggled state.

Files:

- `SceneZero/SceneZero/Views/MainView.swift`

Priority: high.

### 3. Tool Mode Picker Should Not Depend On Drag Alone

Current state:

- The right-side `ToolModePicker` uses a vertical draggable selector.
- It is visually compact and cinematic.

Problems:

- HIG discourages hiding critical mode switching behind gesture-only interactions.
- The picker has `onTapGesture`, but a tap currently only dismisses the adjustment panel, not clearly selects a visible tool.
- Users may not discover that they can drag the control.

Recommended changes:

- Keep drag as an advanced shortcut.
- Add visible tap targets for each tool, at least while the picker is expanded or when the user taps the rail.
- Show a short selected label beside or below the active tool:
  - `角色`
  - `道具`
  - `灯光`
  - `构图`
- Add a compact expanded state:
  - collapsed: current single active tool rail
  - expanded: four 44pt circular buttons in a vertical glass strip
- Add accessibility actions or separate buttons so VoiceOver users can change tools.

Files:

- `SceneZero/SceneZero/Views/MainView.swift`
- `SceneZero/SceneZero/Models/SceneModels.swift`

Priority: high.

### 4. Adjustment Chips Are Too Small For Primary Touch Controls

Current state:

- Inline option chips use 34pt height.
- They are packed inside a horizontal scroll capsule.

Problems:

- 34pt is below the 44pt HIG touch target.
- Horizontal scroll inside a floating side control may be hard to operate one-handed.
- The interaction is powerful but slightly dense for a first competition demo.

Recommended changes:

- Increase chip button hit area to 44pt while keeping the visual capsule around 34-36pt if needed.
- For lens/frame/shot/filter, consider using a `Menu` or segmented row inside a bottom sheet if the side rail becomes crowded.
- Use native labels where possible:
  - `画幅`
  - `镜头`
  - `景别`
  - `色彩`
- For sliders, add a visible min/max semantic label or icon:
  - intensity: `弱` / `强`
  - radius: `窄` / `宽`

Files:

- `SceneZero/SceneZero/Views/MainView.swift`

Priority: medium-high.

### 5. Glass Effect Should Be Purposeful, Not Universal

Current state:

- `liquidGlassRounded`, `liquidGlassCapsule`, and `liquidGlassCircle` are used across cards, chips, controls, and panels.
- The fallback is compatible with older systems because it uses SwiftUI materials and custom overlays.

Problems:

- HIG-style glass should support depth and context, not decorate every surface.
- In the library/detail pages, too many cards using glass can reduce hierarchy and readability.
- Some glass content sits on warm beige backgrounds, where translucency may feel less native than grouped solid surfaces.

Recommended changes:

- Use glass mainly for floating camera overlays:
  - top status bar
  - right-side tool rail
  - shutter-adjacent controls
  - metadata/suggestion pill
- Use solid grouped surfaces for reading-heavy library/detail cards:
  - `Color(.secondarySystemGroupedBackground)` outer background
  - `Color(.systemBackground)` card background
  - subtle separator strokes
- Keep a `LiquidGlassStyle` fallback, but add variants:
  - `.floatingGlassCapsule`
  - `.floatingGlassCircle`
  - `.groupedCard`
  - `.quietPanel`
- Add environment support for Reduce Transparency if possible:
  - if transparency is reduced, use solid system backgrounds.

Files:

- `SceneZero/SceneZero/Views/LiquidGlassStyle.swift`
- `SceneZero/SceneZero/Views/MainView.swift`
- `SceneZero/SceneZero/Views/LookbookView.swift`

Priority: high.

### 6. Lookbook Should Use More Native Grouped Hierarchy

Current state:

- `LookbookView` uses a warm beige background and custom board cards.
- The page has a strong product identity.

Problems:

- `NavigationStack` already provides a native large title; adding another large `Text("灵感库")` inside `libraryHeader` duplicates hierarchy.
- The profile `S` avatar is visually nice, but its purpose is unclear unless account/profile features are real.
- Board cards use glass material, which may make the page feel less like a native iOS library.

Recommended changes:

- Let the native navigation title be the primary title.
- Change `libraryHeader` into a compact privacy/status header:
  - `默认私密 · 本地保存`
  - optional `最近更新 X 个参考包`
- Remove or demote the avatar unless it opens a real profile/settings view.
- Use grouped card surfaces with clear image previews and one or two tags.
- Use `ContentUnavailableView` consistently for empty board/library states.
- Keep board card radius around 16-18pt; ensure inner cover radius follows the concentric rule.

Files:

- `SceneZero/SceneZero/Views/LookbookView.swift`
- `SceneZero/SceneZero/Views/ProfileView.swift` if avatar links there later.

Priority: medium-high.

### 7. Capture Review Sheet Should Feel More Like A Native Sheet

Current state:

- `CaptureReviewSheet` is a `NavigationStack` inside `.sheet`.
- It has cancel in the toolbar and a bottom primary action inside the scroll content.

Problems:

- The sheet would feel more native with clear detents and a stable bottom action.
- The save button inside the scroll can move out of view on smaller screens.
- `TextEditor` cards are readable, but they need stronger focus and keyboard behavior.

Recommended changes:

- Use `.presentationDetents([.medium, .large])` or `.presentationDetents([.large])` depending on final workflow.
- Use `.presentationDragIndicator(.visible)`.
- Move `保存到灵感库` into a bottom safe-area action bar or toolbar confirmation action if it should always be available.
- Keep Cancel top-left and Save top-right only if the sheet is form-like; otherwise keep one prominent bottom CTA.
- Add `submitLabel` or focus management where useful.
- Add a character-light placeholder style that does not compete with typed text.

Files:

- `SceneZero/SceneZero/Views/MainView.swift`

Priority: medium.

### 8. Detail Page Actions Need Clearer Priority

Current state:

- Detail page has favorite and folder menu in the toolbar.
- Copy prompt and export reference image are inside the prompt card.

Problems:

- Primary actions are split across toolbar and card body.
- Export action shares equal visual weight with copy action, although copying prompt is probably the key action.
- Toolbar icons need accessibility labels.

Recommended changes:

- Make `复制提示词` the primary action in the structured prompt card.
- Move `导出参考图` into a secondary `Menu` or lower-priority button.
- Add labels:
  - favorite: `收藏参考图` / `取消收藏`
  - folder menu: `移动到灵感集`
- Consider using `.confirmationDialog` for move/export actions if the menu grows.

Files:

- `SceneZero/SceneZero/Views/LookbookView.swift`

Priority: medium.

### 9. Typography Should Lean More On Dynamic Type Roles

Current state:

- UI uses `.largeTitle`, `.headline`, `.caption`, `.caption2`, `.footnote`, and custom system sizes.

Problems:

- Some important navigation/control labels use `.caption2`, which is very small.
- Camera overlay can use small text, but library/detail reading surfaces should be comfortable with Dynamic Type.

Recommended changes:

- Avoid `.caption2` for primary navigation and important metadata.
- Use:
  - `.largeTitle` only for page-level title
  - `.title3` / `.headline` for card titles
  - `.subheadline` / `.footnote` for metadata
  - `.caption` only for tags and secondary helper text
- Keep text wrapping instead of truncation on detail pages.
- Audit `.minimumScaleFactor`; use it only for compact overlay text, not long content.

Files:

- `SceneZero/SceneZero/Views/RootTabView.swift`
- `SceneZero/SceneZero/Views/MainView.swift`
- `SceneZero/SceneZero/Views/LookbookView.swift`

Priority: medium.

### 10. Color System Should Become Semantic

Current state:

- Warm beige, sage green, and clay/red accents are hardcoded with `Color(red:green:blue:)`.

Problems:

- Hardcoded colors make dark mode and accessibility harder.
- Some semantic roles are unclear:
  - green = privacy / primary / selected tab / save action
  - red-clay = prompt section accent

Recommended changes:

- Introduce a small `SceneZeroTheme` enum or asset colors:
  - `background`
  - `groupedBackground`
  - `cardBackground`
  - `accent`
  - `accentSoft`
  - `warningAccent`
  - `separator`
- Support dark mode with system colors or asset variants.
- Keep sage green as brand accent, but use system blue only when it represents native selection/action expectations.

Files:

- New: `SceneZero/SceneZero/Views/SceneZeroTheme.swift`
- Existing:
  - `RootTabView.swift`
  - `MainView.swift`
  - `LookbookView.swift`
  - `LiquidGlassStyle.swift`

Priority: medium.

## Design Principle For The Next Pass

The capture page can be expressive and glassy because it is a camera overlay. The library and detail pages should be quieter, more native, and more readable. This creates a useful product distinction:

- `取景`: immersive, floating, AR-first.
- `参考图详情`: structured, editable, review-first.
- `灵感库`: calm, private, archival.

## Current Recommendation

Proceed with a focused HIG pass before adding new features. The strongest next iteration is:

**native-feeling bottom navigation + 44pt touch targets + tappable tool modes + restrained glass + semantic theme tokens + more readable library/detail surfaces.**

This is a better next step than adding more AI-video features because the current competition build already has a clear product story; it now needs interaction confidence and iOS polish.
