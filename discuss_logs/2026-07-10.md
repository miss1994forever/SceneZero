## Product Direction From New Design Reference

The new image should be treated as a direction reference, not a pixel-perfect implementation spec. It clarifies the app as a three-step workflow, while the exact layout, wording, and visual density can still be redesigned during coding:

1. **现场取景与 AR 预演**
   - User opens camera on a real location.
   - App detects a horizontal plane.
   - User places simplified characters, light markers, and framing guides.
   - Current UI should feel like a creative viewfinder, not a generic AR demo.

2. **拍摄后进入 metadata 生成**
   - Capture becomes a reference detail.
   - Detail page should communicate:
     - what was captured
     - where it came from
     - key lens/frame/shot metadata
     - what the creator was thinking
     - a structured prompt / metadata package
   - Exact card structure and labels can be adjusted for a cleaner SwiftUI implementation.

3. **私人灵感库长期沉淀**
   - Lookbook should become `灵感库`.
   - Boards should feel like private inspiration sets.
   - Default privacy/local storage should be visible in copy and UI.
   - The page should prioritize inspiration sets / projects over raw image grids.
   - Board card content, tag style, and sample data should be designed in code rather than copied literally from the mockup.

### 3. Restructure PromptService Around Chinese Structured Prompt Sections

Current `PromptService.makePrompt` returns one English comma-separated prompt.

The next iteration should add a readable structured prompt card. The exact fields can evolve, but the first version should separate at least:

- `基础提示词`
- `氛围补充`
- possibly `镜头与空间`
- possibly `保留元素`

Recommended new API:

```swift
struct StructuredPrompt {
    var base: String
    var atmosphere: String
    var shotMetadata: String
    var keepElements: String
    var fullText: String
}
```

Then add:

```swift
static func makeStructuredPrompt(...) -> StructuredPrompt
```

Competition-safe version:

- Use deterministic templates, no online AI dependency.
- Build from:
  - `shotType`
  - `frameAspectRatio`
  - `lensPreset`
  - `filterPreset`
  - `lightRecords`
  - `hasSubject`
  - `locationDescription`
  - user note

Output direction:

- Keep the generated text modular rather than one long paragraph.
- Prefer concise, editable sections over over-specific sample copy.
- Support bilingual output later if downstream AI video tools work better with English prompts.
- Avoid hardcoding one story example such as `父亲的童年` into production logic; use it only as optional demo data.

### 7. Add Liquid Glass Visual Layer With Backward Compatibility

The app can add a Liquid Glass-inspired visual layer, but it should be implemented as progressive enhancement rather than depending only on new system APIs.

Compatibility strategy:

- If compiling against and running on a system that supports native Liquid Glass APIs, use them behind `#available(...)`.
- For older systems, keep a custom fallback using:
  - SwiftUI `.ultraThinMaterial`, `.thinMaterial`, or `.regularMaterial`
  - translucent fills
  - soft strokes
  - subtle highlights
  - restrained shadows
  - consistent corner radius
- Centralize this in `LiquidGlassStyle.swift` so the rest of the UI calls stable helpers such as:
  - `.liquidGlassRounded(cornerRadius:)`
  - `.liquidGlassCapsule()`
  - `.liquidGlassCircle()`

Design guidance:

- Use the glass effect for controls, cards, pills, and floating overlays.
- Avoid making every surface glassy; the app still needs readable hierarchy.
- Prefer compatibility and consistency over chasing a system-only effect that may not run on competition devices.

Files:

- `SceneZero/SceneZero/Views/LiquidGlassStyle.swift`
- `SceneZero/SceneZero/Views/MainView.swift`
- `SceneZero/SceneZero/Views/LookbookView.swift`
- `SceneZero/SceneZero/Views/RootTabView.swift`
