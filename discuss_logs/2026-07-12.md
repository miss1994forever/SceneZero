## Executive Conclusion

SceneZero 当前已有可信的 iOS 原生基础：三项底部导航、沉浸式 AR 取景器、SF Symbols、系统表单与 Sheet、44pt 点击区、SwiftData 本地保存，以及参考图详情中的结构化 Prompt。下一阶段最重要的不是增加装饰，而是让产品的核心闭环在界面上成立：

**发现现实灵感 → 快速记录创作意图 → AR 预演镜头 → 保存为参考包 → 生成/编辑参考图与 Prompt → 按项目和场景继续发展。**

目前的主要断点是：

1. 顶层结构仍以功能命名，缺少“项目/影片”上下文，参考包难以形成故事结构。
2. 拍摄后的详情主要是保存表单，不足以表达“这个场景为什么打动我、下一步想变成什么”。
3. Prompt 只在详情页后段出现，用户难以理解它如何由现场选择逐步形成。
4. 灵感库以文件夹网格为主，缺少时间、地点、标签、场景与镜头序列等多种回看方式。
5. AR 取景器同时呈现较多工具，首次使用时认知负担偏高。

## Skill Synthesis

### ui-ux-pro-max

设计系统搜索返回的“Gen Z Chaos / Maximalism、紫粉 AI 色”不适合 SceneZero：它会与真实画面竞争、降低相机覆盖层可读性，也不符合长期私人影像工作台的克制气质。本方案舍弃该视觉方向，但采用其中可靠的 UX 规则：

- 每屏只保留一个主动作。
- 复杂参数渐进披露。
- 触控目标至少 44×44pt，间距至少 8pt。
- 异步生成超过 300ms 必须显示进度，生成中禁用重复提交。
- 支持 Dynamic Type、VoiceOver、减少动态效果及横竖屏。
- 状态不能只靠颜色表达。

### apple-hig-designer

采用 Clarity、Deference、Depth、Consistency 四项原则：真实场景和参考图始终是主角；系统导航、菜单、Sheet、ShareLink、PhotosPicker 等优先于自定义组件；材质仅用于悬浮在相机画面上的控制层，资料页使用实色 grouped surface；使用语义字体和颜色，而不是固定字号与硬编码颜色。

## Apple App Pattern References

### Final Cut Camera：取景器优先、专业控制渐进展开

- 借鉴点：主界面让画面占据绝大部分空间，曝光、白平衡、焦点等专业参数在需要时展开，选择后持续显示当前值。
- SceneZero 映射：默认只显示快门、当前模式和最关键状态；角色、道具、灯光、镜头等工具点击后进入一个清楚的上下文面板。不要同时展开多个调节条。
- 参考：<https://support.apple.com/guide/final-cut-camera/welcome/ios>

### Freeform：多媒体灵感板，而不是传统相册

- 借鉴点：照片、视频、文档、链接与便签可在同一画布组织；Board 是创作空间，不只是文件夹。
- SceneZero 映射：灵感集详情增加“板 / 列表 / 镜头序列”视图。参考图、现场照片、AI 生成图、文字动机与 Prompt 都是同级素材，可拖动形成关系。
- 参考：<https://apps.apple.com/us/app/freeform/id6443742539>

### Notes：先快速记录，再用标签和智能文件夹整理

- 借鉴点：记录入口轻，标签和 Smart Folder 让内容在不移动原文件的情况下被多维聚合。
- SceneZero 映射：保存时不强迫用户完整分类；自动记录日期、地点、焦段、画幅与现场光，用户只需写一句“我当时想到”。以后通过标签、地点、时间、镜头类型和收藏自动形成智能灵感集。
- 参考：<https://support.apple.com/en-ie/102288>

### Apple AR 设计：让用户理解现实空间与下一步动作

- 借鉴点：AR 应迅速解释可交互区域，持续提供反馈，并避免让界面遮挡真实环境。
- SceneZero 映射：首次进入用短暂的平面扫描状态和明确文案说明“缓慢移动 iPhone，寻找可放置区域”；找到平面后以视觉与轻触觉确认；没有平面时禁用放置并说明恢复方式。
- 参考：<https://developer.apple.com/videos/play/wwdc2022/10131>

## Proposed Information Architecture

### Phone

保留 3 个 Tab，但调整语义：

1. **现场**（`viewfinder`）：现实捕捉、AR 预演、快速记录。
2. **项目**（`rectangle.stack`）：影片/项目、灵感集、参考包和镜头序列。
3. **资料库**（`square.grid.2x2`）：跨项目的全部素材、收藏、地点、标签与智能聚合。

“我的”不应长期占据核心 Tab。当前内容主要是设置与统计，适合移动到“项目”页右上角的头像/设置入口。这样三个顶层位置都服务核心创作。

如果 MVP 暂不实现 Projects，可先保持“现场 / 灵感库 / 我的”，但在灵感库顶部加入项目选择器，并把“我的”降级列为下一阶段调整。

### iPad / Landscape

- 使用 `NavigationSplitView`：左侧项目与智能集合，中间参考包列表/板，右侧详情。
- AR 横屏时工具移到右侧纵向栏，快门保持在右侧拇指可达区域；详情编辑使用侧边 Inspector，避免频繁全屏 Sheet。
- 不在同一层级同时使用自定义侧栏和 Tab Bar。

## Screen-Level Modification Plan

### 1. 现场 / AR 取景页

#### 默认状态

- 顶部左侧显示项目上下文，例如“短片：回声 / 场景 03”，点击打开项目选择 Sheet。
- 顶部右侧最多保留两个动作：构图辅助与更多菜单。重置场景放入 `Menu`，且仅在有已放置对象时启用。
- 中央只显示与环境理解有关的瞬时状态：扫描平面、已锁定平面、跟踪受限、光线不足。
- 快门是唯一视觉主动作；其附近显示当前结果类型“参考包”。
- 工具轨默认折叠，只显示当前工具名称与图标；点击后展开 44pt 的角色、道具、灯光、镜头四项。拖动切换可保留为快捷方式，但不能成为唯一入口。

#### 工具选择与调节

- 选中“角色/道具/灯光”后，底部弹出 compact inspector，而不是在画面上叠多组横向胶囊。
- Inspector 第一层只显示常用项；“更多参数”进入 medium detent Sheet。
- 调节时让被编辑对象出现选中轮廓，并在手指离开后显示短暂值标签。
- 放置、删除、重置分别使用轻/警告触觉。删除后提供 5 秒“撤销”，减少确认弹窗；只有清空整个场景才使用确认对话框。
- 当跟踪或权限失败时，用非模态状态卡显示“原因 + 恢复动作”，不要使用标题为 SceneZero、按钮为“好”的泛化 Alert。

#### 创作意图入口

- 在快门左侧增加一个 44pt 的“语音/文字灵感”按钮（`waveform` 或 `quote.bubble`）。
- 点击后打开半高 Sheet：首行输入“是什么击中了你？”，支持听写，自动保存草稿。
- 该文本与当前 AR 状态持续关联，不必等拍完后再回忆。

### 2. 拍摄后 Review Sheet

将当前保存表单改为三段式，但保持一屏内的渐进披露：

1. **画面**：大图预览，可选择“保留现场 / 生成参考图”。
2. **意图**：主字段“我当时想到”，下方给 2–3 个非侵入式建议标签，如“疏离”“黄昏”“低机位”。
3. **归档**：项目、场景、灵感集；默认继承当前项目，用户可以直接保存。

底部固定主按钮“保存参考包”；AI 生成不应和保存争夺主 CTA。保存后在详情页继续生成。

交互状态：

- 保存中：按钮显示 `ProgressView` 并禁用。
- 成功：轻触觉 + Sheet 缩回到刚生成的参考包卡片，保持空间连续性。
- 失败：字段附近说明原因，并提供“重试”；草稿不能丢失。
- 下拉关闭且有未保存文本时，显示保存草稿/放弃的确认。

### 3. 参考包详情

信息顺序改为：

1. Hero 参考图。
2. “我当时想到”——这是作者意图，优先于机器文本。
3. 镜头摘要——画幅、景别、焦段、构图、灯光，以可点击 token 展示。
4. 参考图变体——现场原图、AR 预演、AI 参考图横向对比。
5. 结构化 Prompt——默认显示简洁摘要，点击“查看全部字段”展开。
6. 导出与复制——使用系统 Share Sheet；按目标平台导出时再选择格式。

Prompt 不应只是一大块只读文本。建议提供字段化编辑：主体、动作、空间、镜头、光线、色彩、氛围、保留元素、避免元素。顶部提供“自然语言 / 结构字段”切换，编辑自动保存；复制后用轻量状态反馈，不长期占据布局。

新增“生成参考图”主动作：

- 生成前显示会使用的参考图和字段，允许取消某个输入。
- 生成中使用固定比例 skeleton，显示阶段文案“分析画面 / 组织镜头 / 生成参考”。
- 结果以可横滑版本呈现，原图永远可回到。
- 失败保留输入并提供“重试 / 调整提示词”。

### 4. 项目 / 灵感库

- 首页顶部不是“默认私密”胶囊占主层级，而是“继续创作”：最近项目、最近参考包、待整理内容。
- 项目卡显示封面、片名、阶段、参考包数量和最后编辑时间；不要重复“x 个场景 · x 个参考包”这种无信息差文案。
- 项目内分为“概览 / 参考 / 场景 / 镜头”四个可横滑但可点击的 segment。
- “镜头”视图支持按顺序拖动；拖动同时提供“上移/下移”菜单和 VoiceOver 可访问动作。
- 空状态的主动作应直接可执行，例如“去现场取景”“导入照片”，而不只是说明文字。

### 5. 全部资料 / 智能集合

- 顶部原生搜索支持标题、备注、Prompt 与标签。
- 快速筛选：收藏、未整理、地点、自然光、夜景、角色、镜头类型。
- 引入非破坏性的多标签；素材可以属于一个项目，同时出现在多个智能集合。
- 使用 PhotosPicker 导入照片/截图；导入后先快速保存，再异步分析建议标签。
- 列表支持 `Grid/List` 切换；Grid 看视觉，List 看镜头与 Prompt 信息。

### 6. 设置

- 使用系统 `Form`，入口放在项目页头像或 `ellipsis` 菜单。
- “导出灵感库”和“取景偏好”必须是真实可点击的 `NavigationLink`/`Button`；当前静态 `Label` 会造成虚假可交互暗示。
- 将 RealityKit 灯光开关放入“AR 与性能”，并用简短说明解释影响。
- 隐私状态使用“所有资料默认保存在此 iPhone”并链接到存储管理，不必在多个页面重复显示胶囊。

## Visual System

### Direction

关键词：**cinematic utility / quiet editorial / content-first**。像一册私人 location notebook，而不是霓虹 AI 控制台。

### Color

- 保留当前 sage green 作为“保存、归档、现场已就绪”的品牌强调色。
- 保留 indigo 作为“AI 分析、Prompt、生成”的次级语义色。
- 警告、失败、删除使用系统 orange/red，不自定义近似色。
- 大面积背景使用 `systemGroupedBackground`、`secondarySystemGroupedBackground` 和 `systemBackground`。
- `accentSoft` 不应固定为浅绿色；需要按 Light/Dark mode 分别定义，或由 accent 低透明度叠加语义 surface，避免暗色模式发灰和对比不足。
- 状态必须同时使用图标/文字，例如“已保存 ✓”，不能仅变绿色。

### Typography

- 全部改用 Dynamic Type 语义样式：`.largeTitle`、`.title2`、`.headline`、`.body`、`.subheadline`、`.footnote`、`.caption`。
- 避免 `.font(.system(size: 13))` 等固定字号用于重要信息。
- Prompt 正文用 `.body`，字段标签用 `.caption.weight(.semibold)`；镜头数字可使用 `.monospacedDigit()`。
- 文本允许换行，Accessibility XXXL 下隐藏次要图标而不是压缩正文。

### Shape, Material, Elevation

- 相机悬浮控件可使用 material，因为需要与动态画面分层。
- 灵感库、详情和设置页使用实色卡片；不把 glass 当作品牌纹理。
- 圆角层级统一为 12/16/20，遵循同心圆角：外圆角 = 内圆角 + padding。
- 卡片主要靠 surface 和间距分组，仅浮层使用阴影。

### Icons

- 统一使用 SF Symbols。
- 顶层未选中用 outline，选中用 fill。
- 多色只用于有真实语义的内容，不随机给工具图标染色。
- 每个 icon-only button 都保留 44×44pt hit area、`accessibilityLabel` 和必要的 `accessibilityHint`。

## Motion And Haptics

- 工具展开、Sheet、保存回库使用 180–300ms 的可打断 spring 动画。
- 动画只表达空间关系：工具从触发位置展开，参考图保存后缩入目标卡片，生成结果在原图位置 crossfade。
- 不给列表卡片做无意义的持续浮动或闪烁。
- 开启 Reduce Motion 时改为 opacity crossfade，取消大幅位移和缩放。
- 触觉只用于平面找到、对象放置、拍摄、保存成功、危险操作五类关键时刻。

## Accessibility And Safety

- 所有交互目标至少 44×44pt，目标间距至少 8pt。
- AR 工具均提供按钮替代，不能只靠拖动、捏合或空间手势。
- VoiceOver 读出对象类型、是否选中、当前位置和可用动作。
- 为排序提供 `.accessibilityAction(named:)` 的上移/下移操作。
- 相机画面上的文字使用高对比 scrim；根据实时画面亮度切换黑/白不是充分方案，必须保留底板。
- 跟踪受限、相机权限、存储失败、生成失败都提供明确恢复路径。
- 横屏、iPad、最大 Dynamic Type、Reduce Motion、深色模式均列为验收场景。

## Validation Plan

用 3 个任务做可用性测试：

1. 用户在街上看到一束有感觉的光，能否在 20 秒内记录画面和一句想法，并确认已保存。
2. 用户能否在 2 分钟内放置人物、选择镜头、拍下 AR 预演并找到生成的 Prompt。
3. 一周后用户能否通过项目、地点或标签找回该场景，并把两张参考图排成镜头顺序。

成功指标：

- 首次完成参考包保存率。
- 从启动到第一次保存的时间。
- 参考包中包含作者备注的比例。
- Prompt 被复制、编辑或导出的比例。
- 一周内重新打开旧参考包的比例。
- AR 首次放置成功率与跟踪失败后的恢复率。

## Key Product Decision

SceneZero 不应被设计成“带 AR 的相机”或“带图片的 Prompt 生成器”。它的独特界面单位应当是 **Reference Package（参考包）**：现实画面、空间预演、作者意图、镜头元数据、参考图变体和结构化 Prompt 在同一个可持续发展的对象中。所有导航和交互都应围绕参考包如何被捕捉、发展、组织和重新使用来设计。
