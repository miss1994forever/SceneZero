## Executive Conclusion

SceneZero 当前已有可信的 iOS 原生基础：三项底部导航、沉浸式 AR 取景器、SF Symbols、系统表单与 Sheet、44pt 点击区、SwiftData 本地保存，以及参考图详情中的结构化 Prompt。下一阶段最重要的不是增加装饰，而是让产品的核心闭环在界面上成立：

**发现现实灵感 → 快速记录创作意图 → AR 预演镜头 → 保存为参考包 → 生成/编辑参考图与 Prompt → 按项目和场景继续发展。**

目前的主要断点是：

1. 顶层结构仍以功能命名，缺少“项目/影片”上下文，参考包难以形成故事结构。
2. 拍摄后的详情主要是保存表单，不足以表达“这个场景为什么打动我、下一步想变成什么”。
3. Prompt 只在详情页后段出现，用户难以理解它如何由现场选择逐步形成。
4. 灵感库以文件夹网格为主，缺少时间、地点、标签、场景与镜头序列等多种回看方式。
5. AR 取景器同时呈现较多工具，首次使用时认知负担偏高。

## Skill Synthesis

### ui-ux-pro-max

设计系统搜索返回的“Gen Z Chaos / Maximalism、紫粉 AI 色”不适合 SceneZero：它会与真实画面竞争、降低相机覆盖层可读性，也不符合长期私人影像工作台的克制气质。本方案舍弃该视觉方向，但采用其中可靠的 UX 规则：

- 每屏只保留一个主动作。
- 复杂参数渐进披露。
- 触控目标至少 44×44pt，间距至少 8pt。
- 异步生成超过 300ms 必须显示进度，生成中禁用重复提交。
- 支持 Dynamic Type、VoiceOver、减少动态效果及横竖屏。
- 状态不能只靠颜色表达。

### apple-hig-designer

采用 Clarity、Deference、Depth、Consistency 四项原则：真实场景和参考图始终是主角；系统导航、菜单、Sheet、ShareLink、PhotosPicker 等优先于自定义组件；材质仅用于悬浮在相机画面上的控制层，资料页使用实色 grouped surface；使用语义字体和颜色，而不是固定字号与硬编码颜色。

## Apple App Pattern References

### Final Cut Camera：取景器优先、专业控制渐进展开

- 借鉴点：主界面让画面占据绝大部分空间，曝光、白平衡、焦点等专业参数在需要时展开，选择后持续显示当前值。
- SceneZero 映射：默认只显示快门、当前模式和最关键状态；角色、道具、灯光、镜头等工具点击后进入一个清楚的上下文面板。不要同时展开多个调节条。
- 参考：<https://support.apple.com/guide/final-cut-camera/welcome/ios>

### Freeform：多媒体灵感板，而不是传统相册

- 借鉴点：照片、视频、文档、链接与便签可在同一画布组织；Board 是创作空间，不只是文件夹。
- SceneZero 映射：灵感集详情增加“板 / 列表 / 镜头序列”视图。参考图、现场照片、AI 生成图、文字动机与 Prompt 都是同级素材，可拖动形成关系。
- 参考：<https://apps.apple.com/us/app/freeform/id6443742539>

### Notes：先快速记录，再用标签和智能文件夹整理

- 借鉴点：记录入口轻，标签和 Smart Folder 让内容在不移动原文件的情况下被多维聚合。
- SceneZero 映射：保存时不强迫用户完整分类；自动记录日期、地点、焦段、画幅与现场光，用户只需写一句“我当时想到”。以后通过标签、地点、时间、镜头类型和收藏自动形成智能灵感集。
- 参考：<https://support.apple.com/en-ie/102288>

### Apple AR 设计：让用户理解现实空间与下一步动作

- 借鉴点：AR 应迅速解释可交互区域，持续提供反馈，并避免让界面遮挡真实环境。
- SceneZero 映射：首次进入用短暂的平面扫描状态和明确文案说明“缓慢移动 iPhone，寻找可放置区域”；找到平面后以视觉与轻触觉确认；没有平面时禁用放置并说明恢复方式。
- 参考：<https://developer.apple.com/videos/play/wwdc2022/10131>

## Proposed Information Architecture

### Phone

保留 3 个 Tab，但调整语义：

1. **现场**（`viewfinder`）：现实捕捉、AR 预演、快速记录。
2. **项目**（`rectangle.stack`）：影片/项目、灵感集、参考包和镜头序列。
3. **资料库**（`square.grid.2x2`）：跨项目的全部素材、收藏、地点、标签与智能聚合。

“我的”不应长期占据核心 Tab。当前内容主要是设置与统计，适合移动到“项目”页右上角的头像/设置入口。这样三个顶层位置都服务核心创作。

如果 MVP 暂不实现 Projects，可先保持“现场 / 灵感库 / 我的”，但在灵感库顶部加入项目选择器，并把“我的”降级列为下一阶段调整。

### iPad / Landscape

- 使用 `NavigationSplitView`：左侧项目与智能集合，中间参考包列表/板，右侧详情。
- AR 横屏时工具移到右侧纵向栏，快门保持在右侧拇指可达区域；详情编辑使用侧边 Inspector，避免频繁全屏 Sheet。
- 不在同一层级同时使用自定义侧栏和 Tab Bar。

## Screen-Level Modification Plan

### 1. 现场 / AR 取景页

#### 默认状态

- 顶部左侧显示项目上下文，例如“短片：回声 / 场景 03”，点击打开项目选择 Sheet。
- 顶部右侧最多保留两个动作：构图辅助与更多菜单。重置场景放入 `Menu`，且仅在有已放置对象时启用。
- 中央只显示与环境理解有关的瞬时状态：扫描平面、已锁定平面、跟踪受限、光线不足。
- 快门是唯一视觉主动作；其附近显示当前结果类型“参考包”。
- 工具轨默认折叠，只显示当前工具名称与图标；点击后展开 44pt 的角色、道具、灯光、镜头四项。拖动切换可保留为快捷方式，但不能成为唯一入口。

#### 工具选择与调节

- 选中“角色/道具/灯光”后，底部弹出 compact inspector，而不是在画面上叠多组横向胶囊。
- Inspector 第一层只显示常用项；“更多参数”进入 medium detent Sheet。
- 调节时让被编辑对象出现选中轮廓，并在手指离开后显示短暂值标签。
- 放置、删除、重置分别使用轻/警告触觉。删除后提供 5 秒“撤销”，减少确认弹窗；只有清空整个场景才使用确认对话框。
- 当跟踪或权限失败时，用非模态状态卡显示“原因 + 恢复动作”，不要使用标题为 SceneZero、按钮为“好”的泛化 Alert。

#### 创作意图入口

- 在快门左侧增加一个 44pt 的“语音/文字灵感”按钮（`waveform` 或 `quote.bubble`）。
- 点击后打开半高 Sheet：首行输入“是什么击中了你？”，支持听写，自动保存草稿。
- 该文本与当前 AR 状态持续关联，不必等拍完后再回忆。

### 2. 拍摄后 Review Sheet

将当前保存表单改为三段式，但保持一屏内的渐进披露：

1. **画面**：大图预览，可选择“保留现场 / 生成参考图”。
2. **意图**：主字段“我当时想到”，下方给 2–3 个非侵入式建议标签，如“疏离”“黄昏”“低机位”。
3. **归档**：项目、场景、灵感集；默认继承当前项目，用户可以直接保存。

底部固定主按钮“保存参考包”；AI 生成不应和保存争夺主 CTA。保存后在详情页继续生成。

交互状态：

- 保存中：按钮显示 `ProgressView` 并禁用。
- 成功：轻触觉 + Sheet 缩回到刚生成的参考包卡片，保持空间连续性。
- 失败：字段附近说明原因，并提供“重试”；草稿不能丢失。
- 下拉关闭且有未保存文本时，显示保存草稿/放弃的确认。

### 3. 参考包详情

信息顺序改为：

1. Hero 参考图。
2. “我当时想到”——这是作者意图，优先于机器文本。
3. 镜头摘要——画幅、景别、焦段、构图、灯光，以可点击 token 展示。
4. 参考图变体——现场原图、AR 预演、AI 参考图横向对比。
5. 结构化 Prompt——默认显示简洁摘要，点击“查看全部字段”展开。
6. 导出与复制——使用系统 Share Sheet；按目标平台导出时再选择格式。

Prompt 不应只是一大块只读文本。建议提供字段化编辑：主体、动作、空间、镜头、光线、色彩、氛围、保留元素、避免元素。顶部提供“自然语言 / 结构字段”切换，编辑自动保存；复制后用轻量状态反馈，不长期占据布局。

新增“生成参考图”主动作：

- 生成前显示会使用的参考图和字段，允许取消某个输入。
- 生成中使用固定比例 skeleton，显示阶段文案“分析画面 / 组织镜头 / 生成参考”。
- 结果以可横滑版本呈现，原图永远可回到。
- 失败保留输入并提供“重试 / 调整提示词”。

### 4. 项目 / 灵感库

- 首页顶部不是“默认私密”胶囊占主层级，而是“继续创作”：最近项目、最近参考包、待整理内容。
- 项目卡显示封面、片名、阶段、参考包数量和最后编辑时间；不要重复“x 个场景 · x 个参考包”这种无信息差文案。
- 项目内分为“概览 / 参考 / 场景 / 镜头”四个可横滑但可点击的 segment。
- “镜头”视图支持按顺序拖动；拖动同时提供“上移/下移”菜单和 VoiceOver 可访问动作。
- 空状态的主动作应直接可执行，例如“去现场取景”“导入照片”，而不只是说明文字。

### 5. 全部资料 / 智能集合

- 顶部原生搜索支持标题、备注、Prompt 与标签。
- 快速筛选：收藏、未整理、地点、自然光、夜景、角色、镜头类型。
- 引入非破坏性的多标签；素材可以属于一个项目，同时出现在多个智能集合。
- 使用 PhotosPicker 导入照片/截图；导入后先快速保存，再异步分析建议标签。
- 列表支持 `Grid/List` 切换；Grid 看视觉，List 看镜头与 Prompt 信息。

### 6. 设置

- 使用系统 `Form`，入口放在项目页头像或 `ellipsis` 菜单。
- “导出灵感库”和“取景偏好”必须是真实可点击的 `NavigationLink`/`Button`；当前静态 `Label` 会造成虚假可交互暗示。
- 将 RealityKit 灯光开关放入“AR 与性能”，并用简短说明解释影响。
- 隐私状态使用“所有资料默认保存在此 iPhone”并链接到存储管理，不必在多个页面重复显示胶囊。

## Visual System

### Direction

关键词：**cinematic utility / quiet editorial / content-first**。像一册私人 location notebook，而不是霓虹 AI 控制台。

### Color

- 保留当前 sage green 作为“保存、归档、现场已就绪”的品牌强调色。
- 保留 indigo 作为“AI 分析、Prompt、生成”的次级语义色。
- 警告、失败、删除使用系统 orange/red，不自定义近似色。
- 大面积背景使用 `systemGroupedBackground`、`secondarySystemGroupedBackground` 和 `systemBackground`。
- `accentSoft` 不应固定为浅绿色；需要按 Light/Dark mode 分别定义，或由 accent 低透明度叠加语义 surface，避免暗色模式发灰和对比不足。
- 状态必须同时使用图标/文字，例如“已保存 ✓”，不能仅变绿色。

### Typography

- 全部改用 Dynamic Type 语义样式：`.largeTitle`、`.title2`、`.headline`、`.body`、`.subheadline`、`.footnote`、`.caption`。
- 避免 `.font(.system(size: 13))` 等固定字号用于重要信息。
- Prompt 正文用 `.body`，字段标签用 `.caption.weight(.semibold)`；镜头数字可使用 `.monospacedDigit()`。
- 文本允许换行，Accessibility XXXL 下隐藏次要图标而不是压缩正文。

### Shape, Material, Elevation

- 相机悬浮控件可使用 material，因为需要与动态画面分层。
- 灵感库、详情和设置页使用实色卡片；不把 glass 当作品牌纹理。
- 圆角层级统一为 12/16/20，遵循同心圆角：外圆角 = 内圆角 + padding。
- 卡片主要靠 surface 和间距分组，仅浮层使用阴影。

### Icons

- 统一使用 SF Symbols。
- 顶层未选中用 outline，选中用 fill。
- 多色只用于有真实语义的内容，不随机给工具图标染色。
- 每个 icon-only button 都保留 44×44pt hit area、`accessibilityLabel` 和必要的 `accessibilityHint`。

## Motion And Haptics

- 工具展开、Sheet、保存回库使用 180–300ms 的可打断 spring 动画。
- 动画只表达空间关系：工具从触发位置展开，参考图保存后缩入目标卡片，生成结果在原图位置 crossfade。
- 不给列表卡片做无意义的持续浮动或闪烁。
- 开启 Reduce Motion 时改为 opacity crossfade，取消大幅位移和缩放。
- 触觉只用于平面找到、对象放置、拍摄、保存成功、危险操作五类关键时刻。

## Accessibility And Safety

- 所有交互目标至少 44×44pt，目标间距至少 8pt。
- AR 工具均提供按钮替代，不能只靠拖动、捏合或空间手势。
- VoiceOver 读出对象类型、是否选中、当前位置和可用动作。
- 为排序提供 `.accessibilityAction(named:)` 的上移/下移操作。
- 相机画面上的文字使用高对比 scrim；根据实时画面亮度切换黑/白不是充分方案，必须保留底板。
- 跟踪受限、相机权限、存储失败、生成失败都提供明确恢复路径。
- 横屏、iPad、最大 Dynamic Type、Reduce Motion、深色模式均列为验收场景。

> 状态：已废弃。该版本仍混入了传统影视项目管理思路，其中“阶段、完成、制作进度、待整理”等建议不再作为设计依据。请以本日志后文“AI 电影定位下的最终修订”为准。保留本段仅用于记录讨论过程。

### 本轮依据与现状判断

本轮结合 `ui-ux-pro-max`、`apple-hig-designer`、当前 SwiftUI 实现和 Apple 第一方产品模式复核。代码中一个 `LookbookEntry` 同时保存 `projectID` 与 `boardName`，但产品没有向用户解释两者为何可以同时存在。这不是单纯的命名问题，而是当前信息架构最核心的歧义：项目与灵感集都表现成“装参考图的容器”。

建议不要合并两者，而是明确为两条正交关系：

- **项目 = 为一部作品服务的制作工作区。** 有目标、阶段、上下文和最终输出；内容会沿着“概念 → 场景 → 镜头 → 参考包/Prompt”发展。
- **灵感集 = 跨项目复用的主题策展。** 没有制作进度，不要求交付；围绕“黄昏逆光、狭长走廊、疏离人物、35mm 手持”等视觉母题收集素材。
- **资料库 = 所有参考素材的唯一总库。** 项目与灵感集都只是组织和查看同一份素材的方式，不复制文件。

这与 Apple Photos 的“Library / Album”模型一致：资料库保存全部内容，相册只是集合，删除相册不删除资料库中的原始素材。参考：<https://support.apple.com/en-nz/guide/iphone/iphc0fc668ab/ios>

### 建议采用的产品心智模型

用一句话向用户解释：

> 在资料库保存每一次发现；用灵感集积累反复出现的视觉母题；当一个想法要被做成作品时，把它放进项目。

三个概念的边界如下：

| 维度 | 项目 | 灵感集 | 资料库 |
| --- | --- | --- | --- |
| 用户问题 | “我正在做哪部作品？” | “哪些画面属于同一种感觉？” | “我保存过什么？” |
| 生命周期 | 有开始、阶段与完成 | 长期积累，可持续增长 | 永久总库 |
| 结构 | 项目 → 场景 → 镜头/参考包 | 主题 → 多个参考包 | 全部素材 + 搜索/筛选 |
| 素材归属 | 一个参考包 MVP 阶段最多归入一个项目 | 可加入多个灵感集 | 必然存在且只有一份 |
| 主要动作 | 继续创作、规划场景、导出参考包 | 收集、比较、排序、寻找风格规律 | 导入、搜索、筛选、清理 |
| 示例 | 《回声》毕业短片 | “潮湿夜路”“窗边侧光” | 所有现场照片、AR 截图、AI 图 |

长期数据模型建议把当前单值 `boardName` 改为可多选关系或标签关系。MVP 暂时保留单灵感集也可以，但界面文案应明确为“加入灵感集”，避免让用户误以为素材被移动出资料库。

### 主导航建议

保留三个顶层 Tab：

1. **取景**：现实观察、AR 预演、拍摄参考图。
2. **项目**：以作品为中心继续创作、组织场景和导出。
3. **资料库**：全部参考包、灵感集、收藏、未整理、搜索与导入。

这三项分别对应“创建入口 / 当前工作 / 长期资产”，职责互补。Apple HIG 将 Tab Bar 定义为顶层区域导航，并强调切换时保留各区域状态；不应把拍摄、导入之类动作伪装成 Tab。参考：<https://developer.apple.com/design/human-interface-guidelines/tab-bars>

#### Tab Bar 视觉与交互

用户提出的方向成立，建议具体化为：

- 移除当前选中项后的绿色 `Capsule`，避免 Tab 看起来像三组大按钮。
- 移除自定义阴影；背景使用系统 Tab Bar 材质。若内容边界不清，只保留 0.5pt separator，不制造悬浮卡片感。
- 选中态使用品牌强调色，同时把 SF Symbol 从 outline 切换为 fill；未选中使用 `.secondary`。颜色不是唯一线索，因为图标形态也变化。
- 保留图标下文字。“变矮”不能牺牲标签和 44×44pt 点击区。
- 当前每项 `minHeight: 52`，外加 top 7 / bottom 6，视觉内容约 65pt（未计安全区）。建议回到系统内容高度约 49pt + Home Indicator safe area，移除多余垂直 padding。
- 切换不需要对整页使用 `.animation(..., value: selectedTab)`；Tab 内容应立即响应并分别保留自己的 `NavigationStack` 和滚动位置。只给图标颜色/形态 150–200ms 的轻微过渡，开启 Reduce Motion 时取消。
- 优先考虑原生 `TabView`，获得系统安全区、VoiceOver“第几个标签/已选中”、状态恢复和未来系统外观适配；仅在 AR 全屏确有布局冲突时保留自定义实现。

### “项目”页修改方案

#### 顶部导航

- 标题仍为“项目”。
- 左上角齿轮目前虽然有 44pt 点击语义，但图标单独出现且入口权重低，也容易被理解为项目设置。
- 建议将个人/全局设置放到右上角，显示 **32pt 头像或首字母圆形按钮，外层保持 44×44pt 点击区**；VoiceOver 标签为“个人资料与设置”。头像比齿轮更能同时表达账户、存储与全局偏好。
- “新建项目”不再与设置放在两个对称的无标签图标中竞争。保留右上角 `plus` 可行，但更推荐空状态和“我的项目”标题行提供明确的“新建”文字动作；已有项目时顶部 `plus` 作为快捷入口。
- 如果右上角空间拥挤，采用“头像在左上 + 新建在右上”也可，但头像必须是真实视觉对象，不再使用裸齿轮。

#### 首屏信息层级

建议从上到下：

1. **继续创作**：最近编辑的项目，而不是最近任意参考包。显示封面、项目名、最近场景/参考包、更新时间；点击回到上次停留位置。
2. **待整理**：只在存在未归入项目的参考包时出现，例如“6 个参考包待整理”，点击进入资料库的“未归档”筛选。
3. **我的项目**：项目卡列表/网格。

当前 `continueCreatingSection` 直接取 `entries.first`，会把“最近素材”误当作“继续项目”。应改为最近更新的 `SceneProject`，项目内再显示最近参考包。

#### 项目卡

- 信息：16:9 封面、项目名、阶段、`x 个场景 · x 个参考包`、最后编辑时间。
- 阶段建议先用 4 个值：构思 / 预演 / 生成 / 完成。没有真实阶段能力前不要展示虚假进度条。
- 卡片整行可点，右侧不必额外添加多个小图标；重命名、归档、删除放入 context menu / ellipsis。
- 空状态主 CTA 为“新建项目”，次动作“从未整理参考包开始”。

#### 项目详情

MVP 先采用三个分段：**概览 / 场景 / 参考包**。

- 概览：一句话创作方向、视觉关键词、最近活动、导出状态。
- 场景：可排序的场景清单，每个场景显示参考包数量和是否已有 Prompt。
- 参考包：仅显示属于本项目的素材，可按场景/未分场筛选。

当前详情只有 `TextEditor + 参考包列表`，不足以体现项目相较于灵感集的价值。只有当项目具备“阶段/场景/输出”至少一项独有能力，项目 Tab 才值得保留。

### “资料库 / 灵感集”页修改方案

#### 页面结构

建议资料库首屏采用原生 segmented control 或顶部筛选：

- **全部**：时间倒序的所有参考包。
- **灵感集**：用户创建的视觉主题集合。

搜索作用于两者；收藏、未整理、现场、导入、AR、AI 生成等作为 filter chips 或筛选菜单，不与“灵感集”混为同级文件夹。

当前首屏直接显示“All / Favorites / 自定义 Board”的网格，会让“资料库”看起来只是文件夹入口，也让用户无法立刻浏览最近素材。应把“最近参考包”或“全部”作为默认视图，将灵感集作为策展视图。

#### 灵感集卡片与详情

- 卡片使用 2×2 拼图封面、名称、素材数量；不要显示项目阶段或更新时间进度。
- 新建灵感集时只要求名称，可选一句视觉描述；不要求选择项目。
- 详情支持 Grid / Moodboard 两种视图。MVP 先做 Grid + 可排序，后续参考 Freeform 的 Board/Scene 思路扩展自由布局。
- 删除灵感集时文案明确：“只删除灵感集，不会删除其中的参考包”。
- 参考包详情中的动作使用“加入灵感集”，允许未来多选；“归入项目”保持单选。这两个动作在语言上必须稳定。

Apple Freeform 允许图像、文字、链接等多种素材存在于同一个 Board，并用 Scene Navigator 定位不同区域；可借鉴其“创作空间”而不是传统目录的思路，但不应在 MVP 直接实现无限画布。参考：<https://support.apple.com/en-gb/guide/freeform/frfm85d6f7b58/mac>

### 取景页的进一步收敛

Final Cut Camera 的价值不在于控件多，而在于取景优先、专业参数按需出现，并让网格、画幅指示、曝光/对焦工具都服务拍摄判断。SceneZero 应采用相同层级：现实画面 > 快门 > 当前上下文 > 临时工具。参考：<https://apps.apple.com/us/app/final-cut-camera/id6469552837>

- 顶部左侧显示当前项目/“随手灵感”，点击可切换，不在拍摄后才第一次要求归档。
- 首次使用默认进入“随手灵感”，不要强迫先建项目。
- 快门继续作为唯一高权重动作；角色、道具、构图、灯光保持同级工具，但同时只展开一组参数。
- 拍摄成功后 Review Sheet 默认继承当前项目；“加入灵感集”为可选，不阻塞快速保存。
- AR 平面扫描、无法放置、跟踪受限、保存中和保存失败必须各有明确状态与恢复路径。

### 视觉系统微调

- 定位为 **quiet cinematic utility**：现实画面和参考图是视觉主角，品牌色只承担选择、保存与就绪状态。
- 相机页允许 material 形成动态画面上的稳定可读层；项目和资料库使用实色 grouped background，避免到处玻璃化。
- 卡片不要依靠重阴影分层。以 surface、8/12/16/24pt 间距和 12/16/20pt 圆角建立层级。
- 使用系统 Dynamic Type；正文不小于 `.body`，辅助信息用 `.subheadline/.footnote`，不使用缩放到 75% 来挤下重要文字。
- 深色模式分别检查强调色、次要文字、separator 和相机 scrim；不能只对浅色值做透明度变化。

### 交互细节与可访问性验收

- Tab、头像、工具按钮的视觉尺寸可以小，但点击区必须至少 44×44pt，目标间距至少 8pt。
- 选中、保存、错误、未整理不能只靠颜色；同时提供图标、文字或形态变化。
- 列表卡片按下只做轻微 opacity/highlight，不让周围布局因 scale 抖动。
- 新建、保存、AI 生成期间禁用重复提交；超过 300ms 显示 `ProgressView` 或固定比例 skeleton。
- 支持 Dynamic Type 最大级别、VoiceOver、Reduce Motion、深色模式、iPhone SE 宽度、Pro Max、横屏和 iPad。
- AR 的拖动、旋转、捏合必须有可见按钮或菜单替代；排序提供 VoiceOver“上移/下移”动作。

### 需要产品负责人确认的问题

以下问题会改变数据结构或核心流程，建议在 P1 前确认；P0 可以先按上述方案推进：

1. **项目是否必须以“场景”作为下一层？** 如果主要用户确实制作电影/短片，建议是；如果更偏单张概念图创作者，则场景层可能过重。
2. **一个参考包能否同时属于多个项目？** 建议 MVP 只属于一个项目，但可加入多个灵感集；这最容易理解，也便于导出。
3. **用户打开 App 的最高频动作是什么？** 建议默认仍进入“取景”；若测试发现大多数用户先整理已有照片，再考虑记忆上次 Tab，而不是现在就改变默认入口。
4. **“项目”的最终产物是什么？** 建议明确为可导出的 Reference Package 集合（参考图 + 结构化 Prompt + 场景/镜头顺序）；没有这个终点，项目容易退化为另一个文件夹。
5. **是否坚持全部本地优先？** 当前设置入口可表达“本地创作空间”；若近期会加入账号/云同步，头像入口比齿轮更有延展性。

### 修正结论

#### 1. 取消“待整理 / 未归档”作为首页重点状态

此前提出“待整理”，是为了提示没有 `projectID` 的参考包。但这是由当前数据字段推导出的工程状态，不是用户真实任务。

SceneZero 的记录应该是低压力的：参考包一旦保存，就已经成功进入“所有灵感”。没有加入灵感集不代表未完成，也不需要提醒或红点。用户可以在未来需要时再加入某个灵感集。

- 出现在首页继续创作区；
- 使用警告、数量 Badge 或待办语气；
- 阻塞保存流程；
- 被命名为“待整理”。

#### 2. 当前实现中的“项目”定位不足

当前 `SceneProject` 在产品上只提供：

- 项目名称；
- 一句话创作方向；
- 一组通过 `projectID` 关联的参考包。

这与“有名称、有主题、有一组参考包”的灵感集没有本质区别。仅仅把容器叫作项目，并不能产生新的用户价值。因此当前阶段同时保留项目和灵感集，会增加选择成本：用户每次保存时都要判断“加入灵感集还是归入项目”，但产品没有给出可感知的区别。

#### 3. MVP 推荐只保留“灵感集”

更收敛的顶层结构：

1. **取景**：现实场景记录与 AR 预演。
2. **灵感**：所有灵感、灵感集、收藏、搜索与导入。

设置/个人资料入口放在“灵感”页右上角头像中。若认为两个 Tab 视觉上过少，也不应为了填满导航而保留没有独立价值的“项目”。取景可以作为突出但仍属于导航的 Tab；导入照片放在灵感页工具栏。

“灵感”页建议结构：

- 默认视图：**所有灵感**，按时间展示全部参考包；
- 次级视图：**灵感集**，围绕中心主题组织，例如“潮湿夜路”“母女关系”“蓝色清晨”；
- 系统集合：收藏；
- 可选筛选：现场拍摄、相册导入、AR 预演、镜头类型、标签。

参考包保存后默认进入所有灵感；“加入灵感集”是可选动作，不要求用户立即分类。

### Storyboard 是否应该成为项目功能

如果未来验证出用户确实需要把灵感发展成一部具体影片，可以再引入“项目”，但项目必须至少包含以下独有能力中的两项：

- 按镜头顺序排列参考包；
- 新建没有现成图片的镜头卡；
- Storyboard / shot list 视图；
- 角色、场景、道具等跨镜头参考；
- 镜头状态，例如构思、已预演、已生成；
- 导出有顺序的参考包或制作 Brief。

这时两者的关系才清楚：

- **灵感集回答“我在收集什么感觉”。**
- **项目回答“我要按什么顺序做出哪部作品”。**

但不建议现在同时加入完整 Storyboard、角色库、场景库和制作管理。这会从“现实灵感 + AR 预演工具”膨胀成前期制片软件。更安全的验证方式是先在单个灵感集中加入一个可切换的“镜头排序”模式：

1. 用户可以给参考包添加镜头编号；
2. 可以拖动排序；
3. 可以插入一张纯文字的镜头想法卡；
4. 可以导出按顺序排列的参考图与 Prompt。

如果用户持续使用这组能力，再把该灵感集“转为项目”，引入角色/场景参考。这样项目是由真实需求成长出来的，而不是预先建立的重复容器。

## 2026-07-12 AI 电影定位下的最终修订

### 产品定位基线

SceneZero 是面向 **AI 电影创作者** 的视觉灵感、现实场景捕捉、AR 镜头预演与生成输入工作台。它把现实画面、空间关系、人物动作、镜头语言和创作意图转化为参考图与结构化提示词，并帮助创作者保持多个 AI 生成镜头之间的视觉与叙事连续性。

SceneZero 不是传统影视制片工具。以下能力明确不进入产品范围：

- 演员表、选角与合同；
- 拍摄日程、通告与现场排班；
- 预算、设备和场地管理；
- 团队任务、审批和制作协作；
- 面向真人拍摄执行的制片流程。

后续判断一个功能是否应当加入，只看它是否至少解决以下一项：

1. 帮助用户发现或记录 AI 电影镜头灵感；
2. 帮助用户预演空间、人物动作或摄影机运动；
3. 提高参考图和 Prompt 的生成可控性；
4. 帮助多个 AI 生成镜头保持角色、场景、动作方向和视觉风格连续。

### 三个核心对象的最终定义

#### 参考包 Reference Package

SceneZero 的基本创作单元，包含：

- 现场照片、导入图片或 AR 预演图；
- 作者的灵感备注；
- 画幅、景别、焦段、机位、灯光和色彩；
- 人物与道具的空间关系；
- 结构化提示词及目标模型适配版本。

参考包不是“等待归档的文件”。保存成功后，它已经自然存在于“所有灵感”中。

#### 灵感集 Inspiration Collection

围绕一个中心主题自由收集参考包，例如“潮湿夜路”“空旷家庭空间”“疏离的母女关系”。

- 没有强制顺序；
- 不要求形成完整影片；
- 同一参考包未来可以加入多个灵感集；
- 用户可以先记录、以后再加入灵感集；
- 不使用“待整理”提醒或未归档压力。

“未加入灵感集”最多作为低权重筛选，不出现在首页、不显示红点，也不阻塞保存。

#### 项目 AI Film Project

项目不是制片项目，而是把参考内容组织成一段 **具有时间顺序和连续性约束的 AI 电影镜头序列**。

```text
AI 电影项目
└── 镜头序列
    ├── 镜头 01：参考图 + 时长 + 镜头运动 + 人物动作 + Prompt
    ├── 镜头 02：参考图 + 时长 + 镜头运动 + 人物动作 + Prompt
    └── 镜头 03：参考图 + 时长 + 镜头运动 + 人物动作 + Prompt
```

项目回答“我要按照什么顺序生成哪些镜头”，灵感集回答“我在收集什么视觉主题”。项目的独立价值来自时间、顺序和跨镜头一致性，而不是名称、文件夹或制作进度。

### 项目的最小功能范围

项目首版只管理与 AI 电影生成直接相关的信息：

- 镜头卡的新增、复制、删除和排序；
- 镜头编号与预计时长；
- 景别、焦段、画幅和机位；
- 摄影机运动：固定、推、拉、摇、移、跟随等；
- 人物动作、视线、进出画方向和画面内位置；
- 道具、光线与空间关系；
- 角色、场景和视觉风格参考图；
- 每个镜头的结构化提示词；
- 跨镜头连续性约束；
- 已生成结果的参考版本（后续能力）。

这里不使用含义模糊的“调度”作为一级字段。将其拆成用户和 AI 模型都更容易理解的三个部分：

1. **人物动作与空间关系**；
2. **摄影机运动**；
3. **镜头内时间变化**。

### 镜头数据与结构化提示词的关系

镜头卡是数据源，结构化提示词是面向某个 AI 视频模型的派生输出。镜头信息不能只保存在一段 Prompt 中，否则难以编辑、排序、比较和适配不同模型。

| 信息 | 镜头卡保存 | Prompt 是否输出 |
| --- | --- | --- |
| 镜头编号 | 是 | 否 |
| 预计时长 | 是 | 根据目标模型能力决定 |
| 景别、焦段、画幅 | 是 | 是 |
| 摄影机运动 | 是 | 是 |
| 人物动作与空间关系 | 是 | 转换成动作和构图描述 |
| 光线与色彩 | 是 | 是 |
| 跨镜头连续性约束 | 是 | 转换成保持/避免描述 |
| 内部状态与备注 | 是 | 默认不输出 |

某些模型通过生成参数控制时长，而不是从 Prompt 读取时长。因此 SceneZero 应保留统一的镜头时长字段，再由平台适配层决定将它写入 Prompt、生成设置或仅作为 Storyboard 信息。

### 最终导航建议

保留三个顶层 Tab：

1. **取景**：现实场景记录、AR 预演和参考包生成；
2. **项目**：AI 电影镜头序列、时长、动作、镜头运动与 Prompt；
3. **灵感**：所有灵感、灵感集、收藏、搜索和导入。

项目 Tab 成立的前提是实现镜头序列能力。在镜头卡、排序和时长尚未实现前，当前项目页只是与灵感集重复的临时占位，不应继续增加传统项目管理元素。

设置/个人资料入口放在项目页或灵感页右上角的头像按钮中；如果希望所有状态都能快速到达，优先放在“灵感”页，因为它更接近全局资料与存储设置。

### Tab Bar 定稿

- 移除选中项绿色胶囊和底部投影；
- 使用系统材质或实色背景，只在必要时保留 0.5pt separator；
- 选中项使用品牌强调色与 filled SF Symbol，未选中使用 secondary + outline；
- 保留文字标签，不做 icon-only Tab；
- 内容高度约 49pt，另加系统安全区；
- 视觉图标可以缩小，但每项触控区域至少 44×44pt；
- Tab 切换立即响应并保留各自导航、滚动和编辑状态，不给整页添加多余转场阴影或缩放。

### 页面结构修订

#### 项目页

- 顶部“继续创作”显示最近编辑的 AI 电影项目和上次镜头；
- 项目卡显示片名、镜头数量、总预计时长、最近编辑时间和 2–4 张镜头缩略图；
- 不显示传统制作阶段、团队、预算或拍摄进度；
- 项目详情默认进入 Storyboard/镜头序列；
- 可在镜头卡中关联已有参考包，也可先创建纯文字镜头再补充参考图；
- 右上角提供明显的头像式个人资料与设置入口，新建项目使用 `plus` 或“新建 AI 电影项目”文字按钮。

#### 灵感页

- 默认展示“所有灵感”，按时间浏览全部参考包；
- 次级入口为“灵感集”，围绕中心主题组织；
- 保存后的参考包直接进入所有灵感，不产生“待整理”状态；
- 参考包详情提供“加入灵感集”和“添加到项目镜头”两个语义明确的动作；
- 收藏、来源、镜头类型和标签作为筛选，不与灵感集混为文件夹层级。

#### 取景页

- 现实画面仍是视觉主角，快门是唯一高权重动作；
- 用户可在“随手灵感”和当前项目镜头之间切换上下文；
- 随手灵感保存后进入所有灵感；
- 从项目镜头进入取景时，保存结果自动关联该镜头并更新对应 Prompt；
- 同时只展开一组角色、道具、构图或灯光参数，避免覆盖真实画面。

### 分阶段实现

#### P0：修正现有界面和概念

- [ ] 删除“待整理”模块和提醒语义；
- [ ] 统一命名为“所有灵感 / 灵感集 / AI 电影项目 / 参考包 / 镜头”；
- [ ] 调整 Tab Bar 高度、选中态、阴影和动画；
- [ ] 把设置入口改为清楚的头像式按钮；
- [ ] 项目页文案明确为 AI 电影镜头工作区，不出现传统制片概念。

#### P1：让项目真正成立

- [ ] 新增镜头卡数据模型；
- [ ] 支持镜头排序、编号和预计时长；
- [ ] 支持摄影机运动、人物动作与空间关系；
- [ ] 镜头关联一个或多个参考包；
- [ ] 根据镜头字段派生结构化 Prompt；
- [ ] 项目卡显示镜头数量与总预计时长。

#### P2：强化 AI 电影连续性

- [ ] 角色、场景与风格参考可被多个镜头引用；
- [ ] 自动提示人物方向、服装、空间布局和色彩连续性冲突；
- [ ] 针对不同 AI 视频模型适配时长、镜头运动和 Prompt 字段；
- [ ] 导出按镜头顺序组织的参考图与结构化提示词包；
- [ ] 保存并对比不同生成版本。

### 最终产品结论

保留项目，但把它严格定义为 **AI 电影镜头与连续性工作区**。灵感集负责围绕中心主题长期收集，项目负责把参考包发展成有时长、动作、镜头运动和先后顺序的 AI 电影镜头。结构化提示词由镜头数据生成，而不是替代镜头数据。任何演员管理、拍摄日程、预算、现场执行或团队制片能力都不属于 SceneZero。

## 2026-07-12 竞品分析：SceneZero 是否需要拓展到“项目”

### 分析问题

本次不是泛泛比较 AI 视频产品，而是回答：

> 对一个以现实场景捕捉、AR 预演、参考图和结构化 Prompt 为核心的 AI 电影 App，独立“项目”是否能提供灵感集无法替代的价值？

评估维度：

1. 产品是否以项目/影片作为顶层容器；
2. 是否存在 Scene → Shot/Frame 层级；
3. 是否支持镜头顺序、时长或 Animatic；
4. 是否保存角色、场景、物体和风格参考；
5. Prompt 是独立文本，还是由镜头数据派生；
6. 是否直接生成视频；
7. 对 SceneZero 可借鉴什么、应避免什么。

### 竞品分组结论

竞品大致分为三类：

1. **灵感画布型**：Adobe Firefly Boards。围绕主题搜集、生成、改图和组织视觉方向，项目结构较弱。
2. **AI 电影项目型**：LTX Studio、Boords、Katalist、Storyboarder.ai。围绕故事、场景、镜头顺序、角色一致性和 Storyboard 工作。
3. **生成工作区型**：Google Flow、Runway。重点是用 Prompt、起止帧、参考素材和模型能力生成/延展视频，项目更多承担素材与生成记录容器。

这个分组说明：**是否生成视频并不是项目存在的唯一理由**。Storyboard/预演产品即使不承担最终剪辑，也会使用项目组织多个镜头；但如果产品只做主题素材收集，灵感集已经足够。

### 核心竞品矩阵

| 产品 | 核心对象 | 镜头顺序/时长 | 一致性参考 | 视频生成 | 对 SceneZero 的启示 |
| --- | --- | --- | --- | --- | --- |
| LTX Studio | Project → Scene → Shot/Storyboard | 强；Storyboard 与 Timeline 连接 | 角色、物体、地点、风格元素跨场景复用 | 是 | 项目成立于“多镜头导演控制”，不是项目名称或文件夹 |
| Adobe Firefly Boards | Board 上的视觉素材与生成结果 | 可做 Storyboard，但结构更自由 | 通过画布上的参考图和生成迭代维持方向 | 是 | 很接近灵感集；自由探索适合前期，但不天然表达镜头连续性 |
| Boords | Project → Storyboard → Frame | 强；Grid、Shot List、Animatic 与 timing notes | Cast reference 自动关联画格 | 可生成帧，重点仍是 Storyboard | 不生成完整电影也需要项目，因为它明确管理镜头序列与时间 |
| Katalist | Project → Script/Storyboard → Frame | 强；从文本形成镜头序列 | 角色参考贯穿整个 Storyboard | 支持 AI Storyboard/视频流程 | 角色一致性和镜头构图是项目层价值，但脚本驱动对 SceneZero 可能过重 |
| Storyboarder.ai | Project → Scene breakdown → Shot list/Storyboard | 强；包含 Shot list 与 Animatic | 参考图指导单个镜头生成 | 提供 AI 生成能力 | 证明“场景拆分 + 镜头序列”是成熟独立品类，但容易扩成全套脚本工具 |
| Google Flow | Project/Scene → clips | 有 SceneBuilder，可把生成片段加入场景并延展 | Ingredients、起始帧和参考素材 | 是 | 强项是把素材直接送入模型；SceneZero 更适合做其上游参考包，而非复制生成器 |
| Runway | Workspace assets + generations | 镜头组织弱于专业 Storyboard 产品 | Character/style/reference media 跨生成复用 | 是 | 一致性参考本身有价值，但不必因此建立复杂项目层级 |

### 1. LTX Studio：最完整的“AI 电影项目”参照

LTX Studio 把脚本或概念转成 Scene 与 Storyboard，并允许逐镜头调整 Prompt、shot type、style、camera movement 和 visual reference。其项目级 Elements 保存角色、物体和地点，使它们可以在多个场景复用。官方还强调用 keyframe 和 camera movement 精确控制每个 shot，并在整个项目中保持一致性。

参考：

- <https://ltx.io/studio>
- <https://ltx.io/studio/platform/ai-movie-maker>

对 SceneZero 的启示：

- “项目”只有在管理多个 Shot 时才成立；
- 角色/场景参考不是传统演员表或场地管理，而是 AI 生成一致性锚点；
- 镜头运动、参考图和 Prompt 应属于同一个 Shot；
- SceneZero 不应复制 LTX 的脚本生成、视频生成、音频和完整 Timeline，否则会失去现实场景 + AR 的差异化。

### 2. Adobe Firefly Boards：灵感集能够覆盖的上限

Adobe 将 Firefly Boards 定位为生成优先的视觉探索空间，可用于 moodboard、storyboard 和 pitch material。用户可以混合参考素材、生成图和视频，在同一画布中发展方向，也可将单个画面转成视频并加入摄影机方向 Prompt。

参考：

- <https://helpx.adobe.com/ca/firefly/web/create-mood-boards/firefly-boards/about-firefly-boards.html>
- <https://helpx.adobe.com/ie/firefly/how-to/create-commercial-storyboard-firefly-boards.html>

对 SceneZero 的启示：

- 灵感集完全可以承担主题探索、参考图比较和早期 Storyboard；
- 如果用户只是围绕主题收集图像、备注和 Prompt，没有必要创建项目；
- 自由画布很适合发散，但对镜头时长、先后关系和跨镜头约束表达较弱；
- SceneZero 的灵感集无需立即实现无限画布，Grid + 自由排序已经能验证大部分需求。

### 3. Boords：不生成最终视频，项目仍然成立

Boords 的重点不是生成完整 AI 电影，而是管理 Storyboard、Shot List 和 Animatic。它提供 Global、Grid、Shot List、Generator 和 Frame Editor 等视图；Frame 可以包含动作、对话、自定义字段、摄影机方向与 timing notes，Animatic 则把画格按时间播放。角色参考可自动关联到相关画格，以维持 AI 生成图的一致性。

参考：

- <https://boords.com/docs/storyboard-views>
- <https://boords.com/docs/creating-storyboards>
- <https://boords.com/docs/concepts>

对 SceneZero 的启示：

- 项目不需要承担视频生成或传统制片，Storyboard 本身就是成立的价值；
- 同一批镜头需要“全局浏览”和“单镜头编辑”两种尺度；
- 时长更适合属于镜头/Animatic，而不是只写入 Prompt；
- Boords 面向传统脚本和客户审阅的功能很多，SceneZero 不应照搬 Script Editor、Review、评论协作等能力。

### 4. Katalist 与 Storyboarder.ai：一致性重要，但脚本驱动可能偏离

Katalist 强调角色跨整个 Storyboard 保持一致，并允许细调 framing、angle、pose、composition、props 和 scene。Storyboarder.ai 则从脚本生成 scene breakdown、shot list、storyboard 和 animatic，并允许参考图指导镜头生成。

参考：

- <https://www.katalist.ai/>
- <https://help.katalist.ai/en/articles/13015400-how-to-add-custom-images-to-your-storyboard-in-katalistai>
- <https://www.storyboarder.ai/>
- <https://help.storyboarder.ai/en/articles/9143185-understanding-the-storyboard-section>

对 SceneZero 的启示：

- 对 AI 电影而言，角色、场景和构图参考的价值是“生成一致性”，不是传统制片管理；
- SceneZero 可以让现实照片、AR 预演图成为角色/场景/镜头参考，这比纯文本拆脚本更有差异；
- 不应把脚本上传、自动拆场、对白管理作为首版项目入口，因为 SceneZero 的独特起点是现实发现，而不是剧本解析。

### 5. Google Flow 与 Runway：项目可能只是生成容器

Google Flow 可以通过文本、Ingredients、Frames 和已有视频生成片段；一致风格的 Ingredients 有助于模型融合参考内容。SceneBuilder 用于把片段加入场景、延展或组织生成结果。Runway 则让参考媒体作为角色、品牌、场景或风格资产反复用于不同生成。

参考：

- <https://support.google.com/flow/answer/16353334?hl=en>
- <https://support.google.com/labs/answer/16935718?hl=en>
- <https://runwayml.com/resources/ai-character-references-tips>
- <https://help.runwayml.com/hc/en-us/articles/52963720640275-Using-reference-media-to-guide-your-generations>

对 SceneZero 的启示：

- SceneZero 不需要复制视频生成；它可以输出适合这些平台消费的镜头参考包；
- 目标模型不同，时长、起始帧、参考图数量和 Prompt 格式不同，因此镜头数据应独立保存，再按平台导出；
- 如果项目只保存“生成记录”，价值会很弱；SceneZero 的项目必须聚焦生成之前的空间预演和镜头设计。

### 竞品共同规律

真正让“项目”成立的能力，出现频率最高的是：

1. **镜头序列**：内容有明确先后关系；
2. **镜头级数据**：画面、动作、摄影机、时长与 Prompt 绑定；
3. **跨镜头引用**：角色、地点、物体或风格参考可以复用；
4. **一致性约束**：不是每个镜头从零开始写 Prompt；
5. **整体预览**：Storyboard、Shot List 或轻量 Animatic；
6. **面向生成器的输出**：将镜头数据适配到不同 AI 视频平台。

反过来，以下能力不足以证明项目有必要：

- 名称和描述；
- 只把一组参考包放进文件夹；
- 收藏、标签、主题封面；
- 没有顺序的自由拖动；
- 单张参考图的 Prompt 生成。

这些都可以由灵感集完成。

### SceneZero 的差异化机会

现有竞品大多从脚本、文字概念、已有图片或模型生成开始。SceneZero 的独特入口是：

> 在真实地点发现画面 → 用 AR 验证人物、道具、光线和构图 → 保存镜头参考包 → 组织成 AI 电影镜头序列 → 导出给视频模型。

因此，SceneZero 不应成为缩小版 LTX Studio 或 Boords。更有价值的项目能力是把“现实空间预演结果”带入多个 AI 镜头：

- 镜头卡直接关联 AR 场景记录，而不仅是静态图；
- 复制镜头后调整人物位置、机位、焦段或光线，快速形成 coverage；
- 从同一现实地点生成远景、中景、特写等一组连续镜头参考；
- 自动比较相邻镜头的人物方向、空间位置、光线和画幅；
- 针对 Flow、Runway、Firefly 等目标平台输出不同形式的参考图与 Prompt。

这是竞品较少覆盖、也最符合 SceneZero 当前技术资产的方向。

### 三种产品路线比较

#### 路线 A：取消项目，只做灵感集

适合条件：用户主要进行单镜头探索、视觉主题收集和 Prompt 生成，很少连续规划多个镜头。

优点：

- 产品最轻；
- 保存流程自然；
- 不需要新增 Scene/Shot 数据模型；
- 取景与灵感库闭环更容易打磨。

风险：

- 难以支持 AI 电影最关键的跨镜头连续性；
- 与相册、Freeform Board 或一般 AI moodboard 的差异缩小；
- “AI 电影”可能退化成“电影感单图/单镜头 Prompt”。

#### 路线 B：立即做完整项目系统

包括 Scene、Shot、Storyboard、角色/场景库、Animatic 和多平台导出。

优点：产品叙事完整，项目价值明确。

风险：

- 开发范围过大；
- 容易复制 LTX、Boords 和 Katalist；
- AR 这一核心差异反而变成附属功能；
- 用户在验证核心价值之前就需要理解复杂层级。

不建议当前采用。

#### 路线 C：渐进式“镜头序列”验证（推荐）

保留项目概念，但先只实现一个可验证的最小闭环：

1. 新建 AI 电影项目；
2. 添加或从灵感引用镜头卡；
3. 镜头卡包含参考图、预计时长、人物动作、摄影机运动和 Prompt；
4. 拖动调整镜头顺序；
5. 以 Storyboard Grid 预览；
6. 导出按顺序排列的参考图与 Prompt。

暂不加入：脚本解析、对白、声音、Animatic 音轨、角色管理后台、多人评审、生成视频和传统制片能力。

这条路线能直接测试“项目是否比灵感集更有用”，同时把范围控制在 SceneZero 的核心上。

### 是否需要项目：当前判断

**有条件地需要，但不应现在把项目做成完整系统。**

理由：

- 如果 SceneZero 真正服务 AI 电影，而不是单张参考图，镜头顺序和跨镜头连续性最终无法由无序灵感集完整表达；
- Boords 证明不生成最终视频也可以靠 Storyboard/Animatic 建立项目价值；
- LTX、Katalist、Flow 和 Runway 共同说明参考素材跨镜头复用是 AI 电影的核心问题；
- 但 Firefly Boards 也证明早期视觉探索完全可以停留在灵感集，不必强迫每个想法成为项目。

因此推荐双入口：

- 所有捕捉默认进入“所有灵感”，不制造待整理状态；
- 只有当用户想把多个参考包组织成连续镜头时，才创建项目；
- 一个灵感集可以继续保持主题集合，也可以选择“用这些灵感创建项目”；
- 项目首屏直接是镜头序列，不再是项目文件夹或统计仪表盘。

### Go / No-Go 验证标准

在正式扩展项目之前，建议用可点击原型或最小实现测试以下任务：

1. 用户能否理解“灵感集是主题，项目是有顺序的 AI 电影镜头”？
2. 用户是否会把至少 3 个参考包放入同一镜头序列？
3. 用户是否会修改镜头顺序、时长、人物动作或摄影机运动？
4. 用户是否认为按镜头导出的 Prompt 比逐张复制 Prompt 更有价值？
5. AR 预演能否自然地从项目镜头进入，并保存回同一镜头？

建议进入项目开发的信号：

- 5 位目标用户中至少 3 位自然创建 3 个以上镜头；
- 至少一半测试用户主动调整镜头顺序；
- 用户能不经解释区分灵感集与项目；
- “按镜头导出参考包”被认为是完成 AI 电影工作流所必需。

建议暂缓或取消项目的信号：

- 用户只给单张参考图生成 Prompt；
- 大多数用户把项目当成另一个灵感集；
- 镜头时长、动作和运动字段长期为空；
- 用户更愿意直接把单个参考包发送到 Flow、Runway 或其他生成器。

### 对当前 UI 方案的影响

在验证完成前，不应把项目设计成沉重的默认入口：

- 取景仍然是默认 Tab；
- 所有内容先进入灵感；
- 项目页空状态用一个示例 Storyboard 解释价值，而不是只显示“创建第一个项目”；
- 新建项目的文案可以是“规划一组 AI 电影镜头”；
- 项目卡只显示镜头缩略图、镜头数量和总预计时长；
- 不显示制作阶段、完成百分比和待办；
- 设置入口可以放在灵感页右上角，避免项目页承担全局首页职责。

### 竞品分析最终结论

SceneZero 可以拓展“项目”，但项目必须是 **现实场景驱动的 AI 电影镜头序列**，而不是传统制片管理，也不是带名称的灵感集。最合理的推进方式不是立即完成全套 Storyboard，而是先验证“参考包 → 镜头卡 → 排序/时长/动作/摄影机运动 → 平台化 Prompt 导出”这一条最小链路。只有当目标用户确实需要组织多个连续镜头时，项目才值得成为长期顶层 Tab。

## 2026-07-12 导航决策：项目暂不进入 Tab Bar

### 与《产品定位.md》的关系

早期定位中最稳定、最有辨识度的部分是：

> 长期积累现实灵感、视觉参考和创作意图，并通过 AR / 2.5D 预演、镜头构图和结构化 Prompt，将它们转化成 AI 视频模型更容易理解的参考输入。

这条价值链不依赖项目才能成立。`产品定位.md` 中的 Projects 主要出现在推荐信息架构，而不是核心痛点或核心价值结论中；“多镜头 story sequence 管理”也被放在远期愿景。因此，项目不应因为早期文档出现过就自动成为当前顶层导航。

早期文档需要后续修正的地方：

- 核心对象不应只写成 Reference Package；更基础的对象应是可包含文字、照片、音频、视频、AR 数据和 Prompt 的“灵感记录”；
- Reference Package 是灵感记录中形成的结构化视觉输入或导出组合，不是每条灵感必须达到的完成状态；
- Projects 应从推荐顶层信息架构移动到“待验证的深度能力”；
- Capture 应同时支持直接拍摄与 AR 预演，不把 AR 固定为后期发展步骤；
- “项目化参考包”不再作为当前产品完整性的必要条件。

### 项目是否应当放进 Tab Bar

当前结论：**暂时不应该。**

Tab Bar 表达的是稳定、高频、对大多数用户都成立的顶层任务。当前项目页只有名称、描述和参考包列表，与灵感集重复；未来的镜头序列、时长和连续性能力尚未验证。此时把项目放进 Tab Bar 会产生三个问题：

1. 暗示用户应当先承诺完成一部作品，削弱低压力记录感；
2. 让用户在“项目”和“灵感集”之间做没有实际价值差异的归档选择；
3. 使 App 看起来像尚未完成的专业 Storyboard 软件，而不是自由灵感与现场预演工具。

项目只有在以下行为被验证后才适合升级为 Tab：

- 用户持续把 3 个以上参考包组织成镜头序列；
- 用户会调整顺序、时长、人物动作或摄影机运动；
- 用户可以自然地区分“灵感集是表达主题，项目是连续镜头”；
- 按镜头导出参考图与 Prompt 是高频需求；
- 项目使用频率足以与“灵感”和“取景”并列。

### 当前推荐顶层导航

#### 方案 A：两个 Tab（推荐）

1. **灵感**：默认首页；时间流、搜索、灵感集、收藏、多模态快速记录和已有灵感的继续发展；
2. **取景**：直接拍摄 / AR 预演，拍摄时可选择是否生成 Prompt。

设置与个人资料放在“灵感”页右上角头像中。

两个 Tab 不是功能不足。它们对应 SceneZero 最稳定的两个用户意图：

- 我想保存或重新发现一个表达欲望；
- 我想在现实空间中形成一张电影参考图。

不应为了视觉上填满底栏而放入低频或未成立的项目入口。

#### 方案 B：项目作为灵感内的可选深层入口

在没有成为 Tab 之前，项目可以用更轻的方式验证：

- 灵感集详情中的“排成镜头序列”；
- 多选参考包后的“创建影像段落”；
- 灵感页中的低权重“镜头序列”区块；
- 参考包详情中的“添加到镜头序列”。

首版甚至不必使用“项目”这个词。用具体动作描述价值，能够减少专业软件压力。如果镜头序列被持续使用，再将其命名为项目并提升导航层级。

### 不提供项目，功能是否过小

**如果只保留当前 AR 截图 + Prompt，确实偏窄；但问题不是缺少项目，而是灵感入口还不完整。**

不含项目的 SceneZero 仍可形成完整闭环：

```text
看到事件 / 构图 / 光影 / 情绪
        ↓
文字、照片、语音、短视频快速记录
        ↓
直接拍摄或现场 AR 预演
        ↓
参考图 + 可选结构化 Prompt
        ↓
保存到所有灵感 / 加入表达主题灵感集
        ↓
以后重新发现、补充和再次预演
```

这已经包含四个有明确价值的能力层：

1. 长期多模态灵感日志；
2. 围绕故事或情感状态的灵感集；
3. 现实场景中的 AR 镜头预演；
4. 面向下游 AI 视频模型的参考图与 Prompt 输出。

它不是单点工具，而是一条从现实经验到生成输入的完整上游工作流。

### 不提供项目，用户面是否过窄

当前目标用户不会因为缺少项目而必然缩小，反而可能更容易进入：

- 正在积累私人影像、短片或实验影像灵感的创作者；
- 还没有完整剧本、但持续记录情绪与场景的人；
- 希望生成单个电影感镜头的 AI 视频创作者；
- 学习镜头语言、需要用 AR 验证构图和站位的学生；
- 广告、MV、动画或游戏概念阶段的视觉创作者；
- 把照片、环境声音和文字逐渐发展成影像的人。

完整项目流程主要扩大的是已经进入多镜头叙事阶段的专业或半专业用户，同时也会提高所有新用户的认知门槛。当前更合理的增长顺序是先扩大灵感记录的频率与媒介类型，再扩展项目深度。

真正需要警惕的是定位过于宽泛。如果只是加入照片、音频和文字，SceneZero 会变成普通日记或素材库。因此每种媒介都要连接到至少一个电影创作动作：

- 从照片进入取景/2.5D 标注；
- 从文字或语音提炼镜头意图；
- 从视频截取参考帧或记录人物动作；
- 从灵感进入 AR 预演；
- 从现场状态生成参考图和 Prompt。

### 产品完整性的判断标准

SceneZero 的完整性不应以“是否拥有项目”衡量，而应以核心闭环衡量：

- 能否在十几秒内保存一个真实灵感；
- 能否在拍摄现场选择直接记录或 AR 预演；
- 能否形成可复用的参考图和结构化 Prompt；
- 能否围绕一个模糊故事或情感长期积累不同媒介；
- 用户数周后能否重新找到旧灵感并继续发展。

只要这五项成立，产品已经完整。项目是进一步解决多镜头顺序与连续性的扩展层，而不是补足核心价值的必需层。

### 最终建议

- 当前移除项目 Tab，采用“灵感 / 取景”两个顶层区域；
- 灵感作为默认首页，强化多模态记录和围绕表达欲望的灵感集；
- 取景保留高效率 Pipeline：看到构图/光影 → 直接拍摄或 AR 预演 → 参考图 + 可选 Prompt；
- 通过灵感集内“排成镜头序列”小范围验证项目需求；
- 在镜头序列行为被验证前，不新增完整项目、Storyboard 或专业流程；
- 后续更新《产品定位.md》，将 Projects 从当前推荐信息架构调整为待验证的扩展能力。

## 2026-07-12 多模态灵感集界面设计

### 设计目标

灵感集不是传统文件夹，也不只是参考图集合。它围绕一个可能仍然模糊的故事、情感状态或表达欲望，长期容纳照片、文字、音乐、环境录音、语音、视频、AR 预演图和结构化 Prompt。

界面应当同时满足：

- 保留内容之间自由、偶然和情绪化的关系；
- 用户追加内容时不需要先排版；
- 图片不会压制文字、音乐与声音；
- 多模态内容仍然容易识别、播放和重新查找；
- 支持 Dynamic Type、VoiceOver、横竖屏和不同设备尺寸；
- 不把灵感集变成需要维护的专业 Moodboard 工具。

### 灵感集详情页结构

#### 1. 表达核心 Header

页面顶部先说明这个灵感集想表达什么，而不是突出文件数量：

```text
疏离的母女关系

我想记录两个人明明生活在同一空间，
却越来越不知道怎样与对方说话。

12 条记录 · 最后补充于今天
```

Header 可以包含：

- 灵感集名称；
- 一段可选的表达描述；
- 内容数量和最后更新时间；
- 可选主题音乐；
- 更多菜单：编辑描述、排序、选择内容、删除灵感集。

描述允许为空，不强迫用户立即说明完整故事。删除灵感集时明确提示“只删除灵感集，不会删除其中的灵感记录”。

#### 2. 多模态情绪流

默认使用 Pinterest 式瀑布流，但不是完全自由尺寸：

- iPhone 采用等宽双列；
- 卡片宽度默认固定，高度随内容变化；
- 图片保持有限范围内的原始比例；
- 音乐、录音、长文字和横版视频可以跨双列；
- 重要内容可由用户设置为“重点”，跨双列显示；
- 不允许默认任意缩放、重叠或自由摆放。

示意：

```text
┌──────────┐ ┌──────────┐
│ 竖版照片 │ │ 文字记录 │
│          │ └──────────┘
│          │ ┌──────────┐
└──────────┘ │ 横版视频 │
┌───────────────────────┐
│ 音乐 / 环境声音       │
│ ▶︎  03:14  ━━━━━━━    │
└───────────────────────┘
```

完全自由的宽高与重叠会增加排版压力，也容易导致阅读顺序、拖动排序、Dynamic Type 和 VoiceOver 出现问题，因此不作为默认方案。

#### 3. 视图和筛选

建议提供两种视图：

- **情绪流**：默认瀑布流，强调内容之间的视觉与情感关系；
- **时间线**：按真实记录时间排列，适合回看某个故事或情感如何逐渐形成，也作为更稳定的无障碍阅读方式。

可选低权重筛选：

- 全部；
- 影像；
- 文字；
- 声音；
- AR / 参考图。

筛选只用于查找，不把不同媒介拆成独立文件夹。

### 卡片类型规范

#### 照片卡片

- 单列显示为主；
- 尽量保留原始比例，但建议把预览比例限制在 `1:1` 到 `4:5`，过长图片裁切后点击查看完整内容；
- 只显示一行必要备注，避免文件名和技术参数覆盖画面；
- AR 预演或导入图片使用小型类型标签区分；
- 点击进入统一灵感详情，而不是直接进入全屏播放器。

#### 文字卡片

- 使用实色 surface，不使用强拟物横线纸或随机便签颜色；
- 默认显示 4–6 行，长文本渐隐并提供“展开”；
- 用户可选择一句话作为摘要；
- 允许 Dynamic Type 自然增高，不通过缩小字号塞入固定卡片；
- 日期和标签降为次级信息。

#### 音乐卡片

音乐优先跨双列显示，不能只显示成一张专辑封面。建议包含：

- 封面；
- 歌曲名与作者；
- 来源：本地音频、Apple Music 链接或外部链接；
- 播放/暂停和当前进度；
- 用户为什么选择这首音乐；
- 可选片段范围，例如 `01:23–01:48`；
- 可选情绪标签。

示意：

```text
┌──────────────────────────┐
│ [封面]  An Ending        │
│         Brian Eno        │
│         ▶︎ ━━━━━━ 03:45  │
│                          │
│ “像记忆逐渐失去边界”     │
└──────────────────────────┘
```

“为什么选择这首音乐”比歌曲元数据更重要，因为它将音乐转化为创作信息。

一首音乐还可以被设为灵感集的“主题音乐”，显示在 Header 下方，作为情绪锚点。但进入页面时不自动播放。

#### 环境录音与语音卡片

- 使用波形，与音乐的专辑封面表达明确区分；
- 显示录制时间、可选地点和时长；
- 语音笔记显示可选自动转写摘要；
- 环境录音允许标注“雨声、远处交通、冰箱低鸣”等声音内容；
- 点击后播放，不自动播放；
- 播放另一段音频时停止当前内容；
- 离开页面后停止或转入系统明确的后台播放状态，不能让声音来源不明。

#### 视频卡片

- 默认显示静态缩略图，不自动播放；
- 显示播放图标和时长；
- 允许用户选择关键帧作为封面；
- 支持从视频截取一帧并进入参考图或 AR / 2.5D 预演；
- 允许对具体时间点添加备注，例如“00:08 人物回头的速度”；
- 横版视频可跨双列，竖版短视频默认单列。

#### AR 参考图与 Prompt 卡片

- 参考图仍是视觉主体；
- 使用低权重标签显示 `AR`、`35mm`、`16:9` 等来源和关键镜头信息；
- 卡片不展开完整 Prompt，只显示一句自然语言摘要；
- 点击详情后查看 AR 场景记录、镜头参数和结构化 Prompt；
- Prompt 是灵感记录的一部分，不制造独立文件或“尚未生成”的未完成状态。

### 排序与布局交互

#### MVP

- 系统根据卡片类型和内容比例自动布局；
- 长按进入选择/排序模式；
- 用户只调整内容前后顺序，不直接控制精确坐标；
- 提供“设为重点 / 取消重点”，决定是否跨双列；
- 拖动必须有清楚的占位反馈和最小移动阈值；
- 排序同时提供“前移 / 后移”菜单及 VoiceOver 自定义动作。

#### 后续可验证能力

如果用户确实需要主动构建图像之间的空间关系，可以增加可切换的 **画布视图**：

- 情绪流负责记录和浏览；
- 画布负责主动构建 Moodboard；
- 时间线负责回看真实积累过程。

画布不作为首版默认视图，也不要求用户为了保存内容而排版。

### 播放与声音规则

- 音乐、语音、环境录音和视频均不自动播放；
- 页面同时最多播放一个声音来源；
- 播放按钮和进度条触控区域至少 44×44pt；
- 显示明确的播放、暂停、已播放和加载失败状态；
- 网络音乐不可用时保留标题、封面、用户备注及重新连接动作；
- 本地文件缺失或被删除时说明原因，不显示空白卡；
- Reduce Motion 开启时取消波形装饰动画和大幅卡片过渡。

### 可访问性与响应式规则

- 瀑布流的 VoiceOver 顺序必须稳定，与内容排序一致，不能按屏幕坐标随机读取；
- 时间线作为放大字体和屏幕阅读器用户的稳定替代视图；
- 不用颜色单独区分照片、音乐、视频、AR 等类型，同时提供图标与文本标签；
- 所有小图标保留 44×44pt 点击区域；
- iPhone 小屏保持两列，但 Accessibility Dynamic Type 下可自动切换单列；
- iPad 使用 3–4 个等宽列，长文本、声音和重点卡片跨 2 列，不无限增加列数；
- 横竖屏切换后保持内容顺序和当前播放状态；
- 图片、视频和音频加载使用固定尺寸占位，避免滚动过程中跳动。

### SwiftUI 实现建议

- 规则 Grid/Timeline 可使用 `LazyVGrid` / `LazyVStack`；
- 真正的瀑布流可以使用自定义 `Layout`，按当前最短列放置卡片；
- 数据顺序必须独立于视觉列位置保存，保证排序、VoiceOver 和主题切换稳定；
- 媒体二进制保存在 App 沙盒，SwiftData 保存路径、类型、尺寸、时长、封面和关系元数据；
- 音频与视频缩略图、波形异步生成并缓存；
- 长列表延迟加载图片和播放器，离屏时释放重资源；
- 不为每张卡片常驻创建视频播放器。

### MVP 范围

首版建议支持：

- 照片；
- 文字；
- 音乐链接或本地音乐条目；
- 环境录音 / 语音；
- 短视频；
- AR 参考图与 Prompt；
- 双列瀑布流；
- 时间线切换；
- 设为重点；
- 基础排序与类型筛选。

首版暂不支持：

- 完全自由画布；
- 任意缩放和卡片重叠；
- 自动播放或多音频同时播放；
- 复杂音乐剪辑；
- 专业视频时间线；
- 为不同媒介建立相互隔离的文件夹系统。

### 最终设计结论

灵感集可以采用 Pinterest 式排布，但应收敛为 **等宽列、可变高度、少数跨列重点卡片**。默认“情绪流”负责自由浏览，时间线负责长期回看和无障碍阅读；音乐、录音、视频、文字、照片和 AR 参考图作为同一表达主题下的平等素材存在。用户只负责记录和调整顺序，系统负责基础排版，避免把自由创作重新变成一项视觉设计任务。

## Validation Plan

用 3 个任务做可用性测试：

1. 用户在街上看到一束有感觉的光，能否在 20 秒内记录画面和一句想法，并确认已保存。
2. 用户能否在 2 分钟内放置人物、选择镜头、拍下 AR 预演并找到生成的 Prompt。
3. 一周后用户能否通过项目、地点或标签找回该场景，并把两张参考图排成镜头顺序。

成功指标：

- 首次完成参考包保存率。
- 从启动到第一次保存的时间。
- 参考包中包含作者备注的比例。
- Prompt 被复制、编辑或导出的比例。
- 一周内重新打开旧参考包的比例。
- AR 首次放置成功率与跟踪失败后的恢复率。

## Key Product Decision

SceneZero 不应被设计成“带 AR 的相机”或“带图片的 Prompt 生成器”。它的独特界面单位应当是 **Reference Package（参考包）**：现实画面、空间预演、作者意图、镜头元数据、参考图变体和结构化 Prompt 在同一个可持续发展的对象中。所有导航和交互都应围绕参考包如何被捕捉、发展、组织和重新使用来设计。
