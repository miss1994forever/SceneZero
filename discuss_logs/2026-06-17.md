# Discussion Log - 2026-06-17

## Topics Discussed

- Whether the next development step should introduce more realistic 3D assets.
- How 3D assets should fit the current SceneZero AR workflow.

## Key Questions

- Can the project introduce more realistic `.usdz` resources as the next step?
- Should the app prioritize realistic assets or multi-page product expansion first?

## Conclusions

- Introducing more realistic 3D resources is a reasonable next step.
- The current app already has the core AR loop: object placement, gestures, Subject / Prop presets, Lookbook, Prompt generation, and Camera-style UI.
- Improving 3D assets will directly improve the visual quality and presentation strength of the AR assignment.
- Multi-page product expansion can come later, after the main AR capture experience feels more complete.
- After true-device testing, hand-converted USDZ props were not reliable enough for the final demo. The course version should prefer stable Apple RealityKit procedural assets by default, then use Reality Composer Pro / Apple-supported USDZ export for future replacement assets.

## Product / Design Direction

- Keep SceneZero positioned as an AR spatial visual reference tool for AIGC film creation.
- Prefer a small set of high-quality, film-previsualization-style models instead of a large asset library.
- Use whitebox or low-poly cinematic blocking models when they communicate scale and scene structure clearly.

## Technical Notes

- Start with 4-6 practical `.usdz` assets:
  - Human mannequin / standing actor
  - Chair
  - Table
  - Sofa
  - Floor lamp or film light stand
  - Camera tripod or cinema camera
- Keep geometry fallback behavior:
  - Load `.usdz` when available.
  - Fall back to primitive meshes when the asset is missing or fails to load.
- Current runtime decision:
  - Chair / Table / Sofa / Lamp Stand should use procedural RealityKit primitives for stable true-device rendering.
  - Converted Kenney `.usdz` files remain reference assets only until re-exported through Reality Composer Pro or another Apple-supported USDZ pipeline.
  - This keeps the implementation aligned with Apple framework conventions and avoids invisible hand-converted USDZ models during the final presentation.
- Visual quality update:
  - Procedural Chair / Table / Sofa presets should not be single simple boxes.
  - They now use multi-part low-poly forms: cushions, backs, arms, legs, crossbars, pillows, and color-separated materials.
  - This keeps the demo stable on device while making the AR props read more like recognizable 3D models.
- USDZ asset update:
  - The first Kenney USDZ conversion used `zip -0 -X`, which stripped ZIP extra fields and made the contained `.usda` data start at byte offset 40 instead of the expected 64-byte-aligned offset. This likely caused true-device RealityKit rendering failure.
  - The converter now uses stored ZIP output without `-X`, restoring local extra fields and matching the alignment pattern seen in the working `Human.usdz`.
  - Chair / Table / Sofa were replaced with more detailed Quaternius Ultimate Furniture Pack OBJ assets, converted to lightweight USDZ files. The pack page marks the assets as CC0.
- Selection / manipulation update:
  - USDZ props should not use oversized static proxy collision boxes.
  - The app now computes a tighter collision proxy from each loaded model's `visualBounds`, then offsets the collision shape to the visible model center.
  - Placement no longer recursively regenerates collision shapes when a loaded USDZ already has an explicit collision proxy.
  - When multiple objects overlap, selection checks the newest placed object first so foreground/recent props are less likely to be stolen by an older large prop.
- Add calibration data to each `AssetPreset`:
  - `defaultScale`
  - `verticalOffset`
  - `defaultYaw`
  - `footprintRadius`
- Watch for common model issues:
  - Incorrect default size
  - Floating above the floor
  - Sinking below the floor
  - Inconsistent forward direction
  - Excessive file size
