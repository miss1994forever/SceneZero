## 未完成项与实施方案

### 1. P0：跨启动的 Capture Review 草稿

- 当前状态：取消前会确认放弃，保存失败时输入保留；但应用被系统终止后，未保存 Review 内容不会恢复。
- 方案：
  1. 增加 `CaptureReviewDraft`（`id`、图片本地路径、标题、备注、board、projectID、创建时间）。
  2. 在文本变更后做 500ms debounce 保存；图片沿用 `ImageStorageService`。
  3. 启动时查找最近草稿，在取景页显示“继续上次参考包”卡片。
  4. 保存为 `LookbookEntry` 后删除草稿及其临时图片；放弃时也删除。
- 验收：杀掉 App 后重新启动，仍能恢复标题、备注、归档位置和图片预览。

### 2. P1：Project → Scene → Reference Package 的 Scene 层

- 当前状态：已实现 Project → Reference Package；尚未有独立的 Scene 实体。
- 方案：
  1. 新增 `FilmScene` SwiftData 模型：`id`、`projectID`、`title`、`synopsis`、`sortIndex`、`createdAt`、`updatedAt`。
  2. `LookbookEntry` 新增可选 `sceneID`；Capture Review Sheet 先选项目，再按项目过滤可选场景。
  3. 项目详情增加“概览 / 参考 / 场景 / 镜头”分段控件；场景支持创建、重命名、排序和查看关联参考包。
  4. 迁移策略：所有历史参考包保持 `sceneID == nil`，在 UI 中显示“未归入场景”。
- 验收：同一项目内的两场戏可独立聚合参考包，移动参考包不会复制图片或 Prompt。

### 3. P2：AI 参考图生成与版本对比

- 当前状态：无法直接实现；工程中没有模型提供商、服务端、密钥管理或图像生成 API 授权。
- 方案：
  1. 定义 `ReferenceImageGenerating` 协议，输入为参考包图片、结构化 Prompt、平台参数，输出任务 ID 与进度流。
  2. 通过服务端代理调用获授权的生成模型；密钥只保存在服务端，iOS 端使用用户会话令牌。
  3. 新增 `GeneratedReferenceVariant`：`id`、`entryID`、`imagePath`、`promptSnapshot`、`provider`、`status`、`failureReason`、`createdAt`。
  4. UI 状态机：`idle → preparing → generating(progress) → succeeded / failed`；固定图片比例 skeleton、取消、重试与“以此版本继续编辑”。
  5. 详情页增加横滑版本轨道，原始现场图永远保留在第一个位置。
- 验收：断网、超时、模型拒绝、重复提交、应用恢复后继续轮询均有明确反馈；原图和 Prompt 不会因生成失败丢失。

### 4. P2：字段级 Prompt 覆盖编辑

- 当前状态：已支持四个平台的文本导出；各字段仍由现场元数据和作者备注自动生成。
- 方案：
  1. 新增可选 `PromptOverrides`（基础、氛围、镜头、保留元素、避免元素）。
  2. 详情页提供“自动生成 / 手动覆盖”切换；仅保存用户修改过的字段。
  3. `PromptService` 合并自动字段和覆盖字段后，再执行平台适配。
  4. 显示“恢复自动生成”按钮和字段级重置，避免不可逆编辑。
- 验收：修改“镜头与空间”不应覆盖作者备注或其它自动字段；切换平台后保留字段含义。

### 5. P2：Freeform 式灵感板、镜头序列与 iPad 布局

- 当前状态：灵感集已有排序模式，但尚无自由画布、列表/板/镜头三视图或 iPad 三栏布局。
- 方案：
  1. 新增 `BoardItemLayout`：`entryID`、`boardID`、`x`、`y`、`zIndex`、`caption`、`updatedAt`。
  2. 灵感集详情使用 `Picker` 切换“网格 / 列表 / 镜头”；镜头视图采用已有 `sortIndex` 和可访问的上移/下移操作。
  3. 画板在 iPhone 使用缩放画布与编辑 Sheet；iPad 使用 `NavigationSplitView`，左侧集合、中间画板/列表、右侧 Inspector。
  4. 拖拽不应是唯一操作：为 VoiceOver 添加移动、置顶、移除等 `accessibilityAction`。
- 验收：iPad 横屏不产生嵌套滚动；网格和镜头排序共享同一参考包；大字号下 Inspector 可读。

### 6. P2：相机控制硬件快捷入口与专业参数

- 当前状态：现有 AR 取景器已支持工具、画幅、镜头、景别、灯光与滤镜；未适配支持 Camera Control 的硬件。
- 方案：
  1. 使用 AVFoundation Camera Control API，仅在硬件能力可用时注册控制项。
  2. 将最常用控制映射为镜头、画幅或曝光意图，不覆盖系统手势。
  3. 设备不支持时保持当前的 44pt 屏幕控件；所有硬件控制都有屏幕替代。
- 验收：支持设备的轻按/滑动与屏幕操作状态一致；不支持设备没有空白或不可用入口。

## 多模态模型、媒体生命周期与瀑布流实现

### 数据模型与迁移

- 新增 `InspirationAsset`，作为 `LookbookEntry` 下可排序的多媒体内容块。
- 支持类型：图片、文字、声音、视频、音乐。
- 资产保存相对路径、外部链接、标题、作者/来源、文字内容、时长、像素尺寸和缩略图路径。
- `LookbookEntry.assets` 使用 cascade delete；删除灵感时 SwiftData 删除相关资产元数据。
- 保留原有 `imagePath`、Prompt 和镜头字段，不进行破坏性重命名或类型修改。
- `InspirationMigrationService` 启动时为旧图片记录补充引用同一 `imagePath` 的 `InspirationAsset`：
  - 不复制原文件；
  - 只处理 `assets.isEmpty` 的旧记录；
  - 可重复执行且不会产生重复资产；
  - 失败时旧 `imagePath` 回退路径仍可显示。
- 新增 Swift Testing 用例验证迁移连续执行两次后只产生一个图片资产；测试已通过。

### 媒体文件生命周期

- 新增 `InspirationMediaStorageService`：
  - 音频写入 `Application Support/InspirationMedia/audio`；
  - 视频写入 `Application Support/InspirationMedia/video`；
  - SwiftData 只保存相对路径，不保存大二进制数据。
- 照片继续使用 `LookbookImages`，新照片和 AR 捕捉同时创建图片资产。
- 视频使用 `Transferable.FileRepresentation` 复制文件，避免将大视频整体加载到内存。
- 录音先写临时目录，用户保存后原子式复制到正式目录；取消、关闭或保存失败会清理临时/正式文件。
- 图片、视频和录音在数据库保存失败时立即回滚已复制文件。
- 删除灵感时同步清理图片、音频、视频及未来缩略图。
- `InspirationFileMaintenanceService` 在成功迁移后清理媒体目录中不再被数据库引用的孤立文件，应对 App 在“复制文件—保存模型”之间被系统终止的情况。
- 增加麦克风用途说明，仅在用户主动选择“记录声音”时请求权限。

### 新增创作入口

- 顶部添加菜单支持：
  - 文字灵感；
  - 现场声音/语音录音；
  - 音乐名称、作者、链接与创作备注；
  - 从照片图库导入视频。
- 照片导入和 AR 捕捉继续保留。
- 首次空状态提供“记录文字”主动作，不再显示错误的搜索无结果状态。

### 多模态呈现

- 新增 `WaterfallLayout`：根据容器宽度自动计算 1–4 列，并将下一张卡片放入当前最短列。
- Accessibility Dynamic Type 自动切换单列。
- `InspirationCard` 根据媒体类型呈现：
  - 图片保留受控原始比例；
  - 文字显示可换行的内容块；
  - 声音显示波形语义和时长；
  - 视频显示播放器语义和时长；
  - 音乐显示音乐信息与创作备注。
- “所有灵感”和灵感集详情均使用瀑布流。
- 详情页新增资产内容区：
  - 本地视频使用 `VideoPlayer`；
  - 录音使用按需创建的 `AVPlayer`，离开页面自动暂停；
  - 音乐链接通过系统 `Link` 打开，不自动播放；
  - 文字和图片使用原生 Dynamic Type 与自适应尺寸。
- 非图片灵感不会显示无意义的镜头、灯光、焦段和 Prompt 字段。
