## 今日完成

- 新增待实施设计方案：Light 改为抽象光位标记。
  - 问题判断：
    - 当前 Light 使用真实灯架 / 灯具 3D 模型，容易让用户误解为场景中的道具或美术资产。
    - SceneZero 的 Light 本质是打光工具，用于记录光源位置、方向、色温、强度和 spread，不应该喧宾夺主地成为画面里的实体器材。
  - 新设计：
    - Light 不再默认显示真实灯具、灯架或 `LampStand` 3D 模型。
    - 添加 Light 时创建抽象 Light Marker。
    - Marker 可采用高透明球体、emissive 小球、细光环、十字定位点或仅选中时明显显示的简洁记号。
    - Marker 需要可选中、可拖动，并能表达光源位置；视觉上保持小尺寸、低遮挡、高透明。
    - RealityKit light 仍负责影响虚拟 Subject / Prop。
    - SwiftUI lighting overlay 仍负责在真实摄像头画面上预览光斑 / 光束。
    - Capture 后合成仍以 overlay 和 Light records 为准，不把真实灯具模型作为参考图主体。
  - 资产策略调整：
    - `LampStand.usdz` 可暂时作为历史资源保留，但不再作为 Light 默认 preset 展示。
    - Light 不进入家具资产选择，也不使用真实灯具模型作为主视觉。
- 已实施对象删除与 Light 抽象 marker：
  - `ARSceneController` 新增选中状态 `hasSelectedObject` 和 `deleteSelectedObject()`。
  - Capture 右侧调节按钮列在存在选中对象时显示 `trash` 按钮。
  - 点击 `trash` 后弹出 destructive 确认弹窗，确认后删除当前选中对象。
  - 删除对象会同步移除 AR entity、对应 `SceneObjectRecord` 和该 Light 的 RealityKit `SpotLight`。
  - 删除最后一盏 Light 后关闭 lighting overlay 状态。
  - 新放置 Light 不再加载 `LampStand.usdz`，改为高透明抽象 Light Marker。
  - Light Marker 保留可选中和可拖动能力，RealityKit `SpotLight` 继续负责虚拟物体打光。
- 修复放置 Light 时 RealityKit / Metal Debug Validation 卡死：
  - 现象：放置 Light 后触发 `fsRealityPbr` / `virtualProbeTextures` 相关 Metal assertion。
  - 原因判断：此前 Light Marker 使用多个半透明 `SimpleMaterial` 子模型，容易触发 RealityKit PBR 透明渲染与环境 probe 资源绑定问题。
  - 修复：Light Marker 改为单个小型 `UnlitMaterial` 球体，避免走半透明 PBR 路径。
  - 额外处理：为 marker 明确设置球形 collision，保留选中与拖动能力。
- 新增并实施 Light 预览分层方案：
  - 保留稳定的 `LightingOverlayView` 作为默认实时打光参考，用于观察光斑 / 光束、色温、强度和 spread。
  - RealityKit `SpotLight` 不再默认创建，避免“先放 Light，再放置 PBR 模型”时触发 Metal / RealityKit validation 卡死。
  - Profile / Workspace 新增 `3D Model Lighting` 高级开关。
  - 开关默认关闭；关闭时 Light 仍有 marker、overlay、Light records、Prompt 和 Capture 后合成。
  - 打开时为已放置和后续放置的 Light Marker 创建 RealityKit `SpotLight`，用于观察虚拟 3D 模型受光效果。
  - 关闭时移除所有 RealityKit `SpotLight`，但保留 Light Marker 和 records。
  - RealityKit `SpotLight` 强度降低到更温和范围，减少渲染压力和设备稳定性风险。
- 修复放置普通物体时额外出现平面的问题：
  - 原因：此前每次放置 Subject / Prop / Light 后都会无条件调用 `addShadowReceiver`，额外创建一个低透明度地面平面。
  - 该平面本意是增强落地阴影，但在当前 AR 预演中会被用户误认为额外物体，且没有随单个对象删除一起管理。
  - 修复：停止无条件创建 shadow receiver，后续放置椅子等普通物体时只显示该物体本身。
  - 同时将 lighting overlay 可见状态统一收敛为由当前 Light records 决定，减少光效状态残留。
- 新增待实施设计方案：Capture 选中对象后删除单个物体。
  - Apple 风格评估：方案可行。
  - 设计依据：
    - 删除是上下文操作，只在用户已经选中 Subject / Prop / Light Marker 后出现，避免在 Capture
      主界面长期暴露低频危险操作。
    - 使用 SF Symbol `trash` 表达删除，符合 iOS 对 destructive action 的常见视觉语言。
    - 删除前提供确认弹窗，避免 AR 场景中误触导致模型丢失。
    - 删除确认使用 destructive role，按钮文案为 `Delete`，取消按钮为 `Cancel`。
    - 删除成功后清空当前选中对象，并用顶部状态提供轻提示，例如 `Object removed`。
  - UI 方案：
    - 当存在选中对象时，在右侧当前调整按钮列中显示 `trash` 图标按钮。
    - 当没有选中对象时，不显示删除按钮，或保持禁用状态；第一版建议不显示，减少视觉噪音。
    - 删除按钮不放在 Capture shutter 附近，避免与拍摄主操作混淆。
    - 确认弹窗不使用长说明，只说明该操作会移除当前选中对象。
  - 实现边界：
    - 只删除当前选中的单个 scene object。
    - 删除后同步移除 RealityKit entity、collision proxy 和对应 layout record。
    - 不影响已经保存到 Lookbook 的历史 capture。
    - 不提供批量删除或撤销；如后续误删反馈明显，再考虑增加 Undo toast。

- 新增待实施设计方案：Lookbook 详情页清晰度提升。
  - 当前 Lookbook 详情图清晰度不足的主要原因不是普通对焦问题，而是保存链路使用
    `ARView.snapshot` 获取实时 AR 渲染画面，再按 Frame Line 裁切；当裁切区域较小或

  - 第二阶段可选方案：
    - 尝试选择设备支持的更高分辨率 AR video format，提高 `ARView.snapshot` 的源画面质量。
    - 如需要更接近系统相机照片的画质，再评估 `AVCapturePhotoOutput` 与 ARKit 的组合方案，但这会显著增加工程复杂度。

## 关键实现

- 人物模型仍沿用现有 `AssetPreset.human` 和 `bundleModelName == "Human"`，
  没有增加新的界面入口或放置逻辑。
- `Human.usdz` 继续走 USDZ 优先加载、primitive fallback 保底的路径。
- 使用 `tools/obj_to_usdz.py` 将 Quaternius OBJ / MTL 转为 USDZ。
- 继续使用修复后的 USDZ 打包方式，不再使用 `zip -X`，保留 ZIP extra fields，避免破坏 USDZ 64-byte 对齐。
- 新模型仍走现有加载策略：
  - 优先加载 bundle 内置 USDZ。
  - 加载失败时回退到 RealityKit primitive fallback。
  - 加载成功后根据 `visualBounds` 自动归一化尺寸，并生成更贴合的碰撞 proxy。
- 放置策略：
  - 只在水平面上放置 Subject / Prop / Light。
  - 如果当前没有可用水平面，顶部状态提示 `Find a horizontal surface`。
