## 修改原因

- 当前 Camera 只是一个 AR 空间里的虚拟机位标记，不改变画面、不影响截图，对 AI 参考图质量帮助有限。
- SceneZero 的定位是 AIGC 电影前制辅助，而不是一般电影拍摄工具或专业摄影机控制工具。
- Frame / Lens 能直接影响实时预览、最终保存图和 Prompt 文本，产品闭环更强。
- Shot Type 如果只修改 Prompt，用户会觉得调节没有反馈；加入构图框、画幅遮罩和截图裁切后，Wide / Close-Up 等选项会更可感知。
- 横屏模式下 AR 画面高度有限，底部面板即使处于紧缩态也会遮挡主要取景区域，因此需要提供完全收起的沉浸式工作状态。
- Light、Frame 和 Capture 设置项数量不同，如果继续用内容自然高度，会导致横屏压缩时重叠、竖屏展开时过高；固定高度加内部滚动更符合移动端工具面板模式。
- 内部滚动已经解决“查看更多内容”的问题后，`More / Less` 会造成重复层级；移除后用户只需要理解“滑动查看更多”和“完全收起”两种状态。
- 右下角浮动入口更符合 iOS 辅助工具入口的触达和视觉逻辑，也能减少对画面中心构图区域的遮挡。
- `.ultraThinMaterial` 圆形浮层比大面积底部按钮更轻，符合 AR 取景界面中“工具入口让位于画面”的原则。
- Capture 是创作流程的主动作，和 Subject / Prop / Frame / Light 参数调节不属于同一层级；独立出来能减少面板重量，也能保证沉浸模式下仍可截图。
- Lookbook 是历史结果管理页面，作为独立入口更符合 iOS 的页面导航逻辑。
- 紧凑图标工具栏比四个大卡片更接近 iOS 工具型界面，减少了面板高度和文字重复。
- 项目需要本地 UI 规范，避免后续只凭截图感觉修改；`apple_ui_guidelines.md` 可以作为每次 polish 前的检查清单。
- 多界面、内置资产和手势交互可以显著提升项目完成度，但都需要控制范围：课程版不引入云端素材库、不做在线电影图库、不做账号系统。
- 先实现 Subject / Prop 的直接操控，可以在不引入新素材的前提下明显提升 AR 搭场景体验；Light 的移动需要后续把 marker、beam 和 SpotLight 封装成统一可移动对象后再做。
- Camera-style 工具滑动选择器比固定工具面板更适合 Capture 主界面：取景时只显示当前工具，选择工具时才短暂展开。
- 白色圆形 shutter 比蓝色矩形按钮更接近 Apple Camera 的视觉语言；固定选择位工具栏比展开菜单更像 Camera mode picker。
- 将拖动预览和最终选中拆开后，工具栏在接近选中阈值时不会因为 `selectedTool` 变化而闪现重排。
- 降低工具栏拖动灵敏度后，工具选择更接近相机 mode picker 的“有阻尼”手感。
- AssetPreset 先作为数据层落地，可以在不引入素材文件和模型加载风险的情况下，为下一步内置 USDZ 和 UI preset 选择打基础。
- 先用几何组合模型覆盖常用 Subject / Prop 类型，可以明显提升搭景表达力，同时避免课程周期内被模型资源下载、授权和 bundle 体积拖慢。
- 资产 preset 接入 UI 后，用户可以在“选择工具”和“选择要放置的对象类型”之间形成清晰心智模型：Subject / Prop 决定类别，Asset 决定具体占位物。
